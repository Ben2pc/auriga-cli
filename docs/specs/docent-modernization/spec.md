# docent modernization — Spec (`docent` 现代化 — 规范)

> 保留 `docent` 的独立讲解制品价值，减少新模型生成报告时不必要的强制内容与视觉差异化负担。

## Why (为什么做)

`docent` 的价值不在于补足模型阅读代码的能力，而在于把大范围代码阅读隔离到专职上下文，并交付一份适合人类快速建立心智模型的可视化报告。它只在用户明确选择时运行，因此不属于需要因模型升级而删除的默认工作流约束。

当前报告契约仍把所有定位方式、九类内容和每次不同的视觉风格都写成强要求。对更强的模型而言，这会鼓励为了满足清单而填充历史、体验路径或定制样式，即使它们不能帮助理解当前问题。此次调整要保留讲解质量的承重部分，同时允许模型根据代码形态选择真正有用的证据和表达方式。

## Findings (调研发现)

- 当前主技能只有约 108 行，主要体积来自可复用渲染资产与确定性测试，而不是常驻提示词；见 `plugins/auriga-workflow/skills/docent/` 与 `tests/docent-skill.test.ts`。
- 当前技能只允许用户显式调用，并用单个专职子代理隔离定位、通读、合成和报告生成过程；见 `plugins/auriga-workflow/skills/docent/SKILL.md`。
- 当前报告要求九类内容全部出现，窄范围只能显式标注“不适用”；其中历史演化与人工端到端体验并非对所有代码主题都有解释价值。
- 当前设计规范要求每份报告选择不同的美学方向，并要求版式持续定制；固定组件和拼装机制已经能提供稳定、可读的视觉基线。
- Claude Code 当前正式文档支持 `disable-model-invocation: true` 作为人工调用门禁，但本机 Claude Code 与 Codex 的技能校验脚本仍把它判为未知字段。该差异属于运行时扩展与通用校验规则不一致，不代表应删除人工调用门禁。
- 无项目专属 spec 规则。

## What (做什么)

### 1. 保留独立讲解制品

- `docent` 继续只由用户明确选择，不因普通代码问答自动生成重型报告。
- 定位、通读、合成和生成继续由一个专职子代理完成；运行时不支持子代理时才在主对话降级执行，并向用户说明上下文影响。
- 产物继续是写入临时目录的单文件离线报告，带文件行号锚点、阅读足迹和纠偏入口。

### 2. 区分核心内容与条件内容

每份报告必须讲清：为什么存在、入口与主流程、代码地图、关键数据或状态、相邻契约与不明显约束，以及阅读足迹。第一屏继续提供整体结构图，主流程继续使用合适的标准软件工程图，代码结论继续附可追溯锚点。

历史演化只在版本历史能解释当前结构或用户明确关心时展开。人工端到端体验只在目标存在可运行或可操作入口时展开；否则使用适合该代码形态的测试、检查或阅读证据，不为满足清单虚构体验路径。

### 3. 让定位和视觉表达按问题选择

- 文件名、符号、字符串、调用关系和版本历史等定位手段作为工具箱，按问题使用，不要求每次全部执行。
- 报告默认复用稳定的组件、色板和可读性规则。只有当定制版式能明显改善当前主题的理解时才增加定制，不再以“每份报告看起来不同”为质量目标。
- 现有机械拼装、离线渲染和错误可见降级能力继续保留。

### 4. 保留双运行时边界

Claude Code 继续使用其正式支持的人工调用门禁；其他不识别该扩展的运行时通过技能描述和正文遵守同一触发边界。验证时运行两端官方技能校验工具，并把已确认的运行时扩展差异显式报告，不能为了消除已知校验告警而改变产品行为。

## Out of scope (本次不做)

- 不删除 `docent`，也不改变为默认自动调用。
- 不改为多个并行子代理，不引入跨会话报告存档或索引。
- 不替换现有报告资产、渲染器或拼装脚本，也不增加新的报告格式。
- 不开展模型评测；本轮只依据现有使用场景、代码契约和确定性验证做精简。
- 不调整 `docent` 之外的技能或工作流。
