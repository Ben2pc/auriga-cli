# `docent` 评审

## 当前职责

`docent` 是用户显式选择的代码理解工具。它把大范围代码定位和通读隔离到单个专职子代理，并交付带整体结构图、主流程图、代码锚点和阅读足迹的离线报告。它不参与默认开发流程，也不替代普通的代码问答。

## 可复现失效模式

- 普通对话中的大范围代码阅读会挤占主会话上下文，压缩后容易丢失先前决策。
- 纯线性文字难以同时表达代码位置、跨文件调用关系和状态变化，人类需要反复追问才能建立空间与流程心智模型。
- 模型自行定位主题时可能漏掉相关文件；没有阅读足迹时，用户难以发现定位偏差。
- 没有文件行号锚点的讲解难以核对，代码变化后也无法判断结论来自哪里。

## 目标模型证据

本轮没有执行 GPT 5.6 Sol 或 Fable 5 的模型评测，因此不声称目标模型不能原生完成代码讲解。保留结论依据的是产物形态和上下文隔离仍有独立价值，而不是模型能力不足。

新模型降低了固定搜索步骤和弱模型检查清单的必要性。当前可直接精简的部分是：无条件搜索版本历史、九类内容全部占位，以及每份报告都追求不同视觉外观。

## 与其他资产的关系

- 普通代码问答由当前 Agent 直接完成；只有用户明确选择 `docent` 才生成重型报告。
- `session-compound` 总结会话，`docent` 解释代码；两者都生成临时离线报告，但输入、生命周期和阅读目标不同。
- `documentation-and-adrs` 维护长期文档，`docent` 报告是代码变化后可能失效的即时制品，不进入仓库文档资产。
- 固定渲染器、组件样式和拼装脚本承担确定性机制，避免模型重复生成机械资产；它们不属于需要随模型升级删除的提示词约束。

## 处置结论

结论为**精简**：保留显式调用、单子代理隔离、离线报告、第一屏整体结构图、主流程标准图、代码锚点和阅读足迹；将定位方式改为按需工具箱，将历史演化和人工端到端体验改为条件内容，视觉设计改为稳定基线优先。

不删除该技能，因为删除会同时失去隔离上下文和可视化离线制品。也不改成自动触发，因为普通代码问题不应承担生成重型报告的成本。

## 成本与维护权

主技能正文较短，主要维护成本来自渲染器、组件和对应测试。这些资产已经把图表渲染与离线拼装变成确定性机制，能复用于每次报告，因此当前维护成本与产物价值匹配。

Auriga 应继续拥有该技能：它与 Auriga 的子代理能力、双运行时边界、临时制品约定和组件资产直接耦合，外部通用技能无法稳定承载这些产品契约。

## 风险、观察信号与恢复条件

| 风险 | 观察信号 | 有界恢复条件 |
|---|---|---|
| 条件式历史演化导致关键设计动机被漏掉 | 用户反复指出“当前代码看不出为什么这样设计”，且补读相关提交后才能解释 | 强化“当前结构无法自解释”时的历史触发条件；只有该信号持续出现时，才把历史演化恢复为对应主题的必写项 |
| 条件式验证内容让报告缺少可操作的确认路径 | 对存在真实运行入口的主题，报告连续遗漏启动方式、操作步骤或预期现象 | 强化可运行目标的验证触发；不把人工端到端要求恢复到纯库、配置或静态代码主题 |
| 稳定视觉基线不能表达复杂状态或宽依赖图 | 用户需要反复缩放、跳转或口头补充才能理解关键关系 | 为该类图增加专用组件或明确的定制条件；不恢复“每份报告必须视觉不同”的目标 |
| 按需定位漏掉外围代码 | 阅读足迹中持续出现用户补充的同类遗漏来源 | 把该遗漏来源加入对应条件的定位提醒；不恢复所有搜索方式每次必跑 |
