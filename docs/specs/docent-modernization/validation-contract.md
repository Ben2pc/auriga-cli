> 每条 VAL 只描述 Behavior + Tool + Evidence；测试设计由测试驱动开发阶段决定。

## Assertions (断言)

### VAL-DOCNT-001
- **Behavior (行为)**: `docent` 继续只由用户明确选择，并由单个专职子代理隔离完成代码定位、通读、合成和报告生成；无法派遣时才允许在主对话降级并告知影响。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 技能的触发与执行契约同时保留人工调用边界、单子代理要求和无子代理时的显式降级说明。

### VAL-DOCNT-002
- **Behavior (行为)**: 每份报告必须覆盖存在原因、入口与主流程、代码地图、数据或状态、相邻契约与不明显约束、阅读足迹，并保留第一屏整体结构图、主流程标准图和文件行号锚点。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 技能正文将这些内容和表达形式列为不可静默省略的核心报告契约。

### VAL-DOCNT-003
- **Behavior (行为)**: 历史演化和人工端到端体验只在它们能解释当前代码或目标确实存在可操作入口时展开，不要求用无效内容填满报告。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 技能将两项标为条件内容，并为不适用场景允许使用更合适的验证或理解证据。

### VAL-DOCNT-004
- **Behavior (行为)**: 代码定位方式按问题选择，文件名、符号、字符串、调用关系和版本历史不再是每次必须全部执行的检查清单。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 技能把定位手段表达为按需工具箱，且没有要求无条件执行全部搜索方式。

### VAL-DOCNT-005
- **Behavior (行为)**: 报告默认复用稳定、可读的视觉基线，仅在定制能改善理解时调整版式，不再要求每份报告追求不同外观。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 设计规范保留组件、色板、层级、图表和可读性要求，同时不含必须制造视觉差异或无条件生成定制样式的要求。

### VAL-DOCNT-006
- **Behavior (行为)**: 人工调用门禁在 Claude Code 中继续由正式运行时字段执行，其他运行时继续获得等价的文字边界；官方校验器与运行时扩展不一致时显式报告差异，不通过删除门禁换取无告警结果。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 技能保留人工调用字段及跨运行时描述；两端官方校验工具均被执行，已知扩展字段告警被记录为兼容例外，除此之外无校验错误。

### VAL-DOCNT-007
- **Behavior (行为)**: 精简后的正式评审记录必须说明可能丢失的讲解质量、可观察信号和有界恢复条件，避免报告质量下降时无依据地恢复整套旧清单。
- **Tool (工具)**: `repo-check`
- **Evidence (判据)**: 评审记录分别列出历史脉络遗漏、验证路径不足或稳定版式影响理解时的观察信号，并把恢复动作限制为提升对应条件的触发强度或恢复单项要求。
