# Validation Contract — session-compound 现代化 (验收契约 — session-compound 现代化)

> 与 spec.md 配套：spec.md 描述 why+what；本文件描述“什么算通过”。
> 每条 VAL 只描述 Behavior + Tool + Evidence；测试函数、夹具和内部拆分由测试驱动开发阶段决定。

## Coverage map (覆盖矩阵)

| Range (范围) | VAL ids |
|---|---|
| 模式与报告交付 | VAL-MODE-001 ~ VAL-MODE-004 |
| 技能使用证据 | VAL-SKIL-001 ~ VAL-SKIL-003 |
| 事实与判断边界 | VAL-EVID-001 ~ VAL-EVID-002 |
| 近期使用洞察 | VAL-INS-001 ~ VAL-INS-004 |
| 建议与长期候选 | VAL-CAND-001 ~ VAL-CAND-005 |
| 独立评估 | VAL-EVAL-001 |
| 人工确认 | VAL-FLOW-001 |

## Toolchain (本仓库验证栈)

> A1 调研所得的既成事实，不是本次功能的实现决策。只列本契约实际使用的类别。

| Category (类别) | This repo's concrete tool (本仓库具体工具) |
|---|---|
| `unit-test` | Node.js 测试运行器；`npm run test:session-compound` 执行分析器与近期洞察管线两组测试 |
| `repo-check` | Node.js 文件内容与结构断言；仓库级契约测试由 `npm test` 执行 |
| `manual` | 使用代表性的 Claude Code 与 Codex 会话生成离线报告，并在浏览器中检查证据、空态与交互结果 |

## Assertions (断言)

### VAL-MODE-001
- **Behavior (行为)**: 每次调用 `session-compound` 都先让用户选择“单会话复盘”或“近期使用洞察”，未选择前不自动进入任一模式，一次调用只生成所选报告。
- **Tool (工具)**: repo-check
- **Evidence (判据)**: 技能入口存在明确的二选一交互；两条选择分别进入唯一对应模式，不存在含糊措辞默认分流或一次生成两份报告的路径。

### VAL-MODE-002
- **Behavior (行为)**: 单会话模式对当前或用户指定会话生成可离线打开的报告，覆盖会话叙事、执行健康度、独立评估和长期沉淀候选四类信息。
- **Tool (工具)**: manual
- **Evidence (判据)**: Claude Code 与 Codex 各用一份代表性会话生成报告；报告无需联网即可打开，四类信息均有可访问入口，已有数据能够呈现。

### VAL-MODE-003
- **Behavior (行为)**: 近期洞察模式分析当前运行时最近 30 天的可读会话，并显示实际覆盖日期、发现的会话总数、成功分析数和未纳入语义分析数；样本不足时明确限制且不声称存在跨会话趋势。
- **Tool (工具)**: manual
- **Evidence (判据)**: 用覆盖已知日期、同时含有效、过短和损坏记录的会话集合生成报告；范围与各项数量可核对，证据不足的输入只显示事实摘要或限制，不生成“反复出现”结论。

### VAL-MODE-004
- **Behavior (行为)**: 两种模式对相同输入都能稳定生成结构完整的最终报告，执行者不需要人工修改报告源码；某类证据缺失时显示未知状态或合法空态，而不是零值或破损区块。
- **Tool (工具)**: repo-check
- **Evidence (判据)**: 自动化契约能够从两种模式的固定输入产出最终报告并检查关键数据入口与结构；流程不要求模型或用户按位置编辑报告源码，删除可选证据后仍能生成可打开的完整报告。

### VAL-SKIL-001
- **Behavior (行为)**: 运行时提供明确技能调用或注入事件时，报告把它计为“显式调用”，并保留技能名称与次数。
- **Tool (工具)**: unit-test
- **Evidence (判据)**: 含多个显式技能事件的输入输出对应名称和精确次数，且每条记录带可区分于推断使用的证据类型。

### VAL-SKIL-002
- **Behavior (行为)**: Codex 会话读取适用的 `SKILL.md`、但没有显式 `<skill>` 注入时，报告仍能识别“推断使用”，不会显示技能使用次数为零，也不会把推断证据冒充显式调用。
- **Tool (工具)**: unit-test
- **Evidence (判据)**: 含 `SKILL.md` 读取事件而不含 `<skill>` 块的输入输出非空技能使用列表；对应记录明确标为推断证据。

### VAL-SKIL-003
- **Behavior (行为)**: 同一用户轮次内对同一技能的重复读取、分段读取或等价路径读取不会被放大成多次推断使用，不同用户轮次中的再次使用仍分别计入；两类使用证据都进入逐技能执行评估范围。
- **Tool (工具)**: unit-test
- **Evidence (判据)**: 单轮多次读取同一技能只形成一次使用事件，跨两个用户轮次形成两次，等价路径不产生重复技能；仅有推断使用的技能仍出现在评估输入且保留证据标签。

### VAL-EVID-001
- **Behavior (行为)**: 非零工具退出作为原始事实保留，但预期失败、异常失败和无法判断的失败不会未经证据统一标记为浪费。
- **Tool (工具)**: unit-test
- **Evidence (判据)**: 同时含失败测试、存在性探测和真实命令错误的输入保留全部原始事件；只有具备相应证据的事件被归类，未知事件保持未知，浪费数量不等于原始非零退出总数。

### VAL-EVID-002
- **Behavior (行为)**: 规则、技能目录、满意度、摩擦和趋势的结论标明证据性质与来源时点；缺少会话时快照或明确用户信号时保持未知或注明为模型分析，不伪装成历史事实或机械统计。
- **Tool (工具)**: unit-test
- **Evidence (判据)**: 有历史快照与明确信号的输入能够标明对应来源；只有当前规则或语义推断的输入显示“按当前规则回看”或“分析结论”，并能追溯到代表性会话，不产生无依据的历史违规或精确计数。

### VAL-INS-001
- **Behavior (行为)**: 近期洞察报告顶部用简短一览分别概括有效模式、主要阻碍、可立即尝试的改进和更进阶的工作流，并可导航到正文证据。
- **Tool (工具)**: manual
- **Evidence (判据)**: 代表性多会话报告包含四部分一览，每部分都能定位到正文中的相应领域、摩擦、建议或代表性会话，而不是只有泛化评价。

### VAL-INS-002
- **Behavior (行为)**: 近期洞察报告说明主要项目领域、交互方式、有效工作流和反复摩擦；“反复”结论至少由两个独立会话支持。
- **Tool (工具)**: manual
- **Evidence (判据)**: 人工抽查每项反复模式均可追溯到至少两个不同会话；只出现一次的事实被表述为单次观察，不会被写成长期习惯。

### VAL-INS-003
- **Behavior (行为)**: 近期洞察把 Agent 侧阻碍与用户侧或环境侧摩擦分开，并同时报告有效模式和问题，不把复盘收窄为只找缺陷。
- **Tool (工具)**: manual
- **Evidence (判据)**: 含两侧摩擦和正向信号的多会话输入生成的报告分别呈现各方责任与后果，并保留至少一个有证据的有效模式；缺少某一侧证据时不强行补齐。

### VAL-INS-004
- **Behavior (行为)**: 近期洞察可以提出当前运行时已有能力、新工作方式或可复制提示词作为“值得尝试”，每条说明为什么适合这些会话以及如何低成本尝试。
- **Tool (工具)**: manual
- **Evidence (判据)**: 人工抽查每条建议都能追溯到真实会话模式，包含具体试用方式或可复制提示词，且不会要求先修改长期工程规则才能验证价值。

### VAL-CAND-001
- **Behavior (行为)**: 两种模式都允许零条“值得尝试”和零条长期沉淀候选，并把空结果表述为合法完成，而不是错误或内容缺失。
- **Tool (工具)**: manual
- **Evidence (判据)**: 对没有新模式、或反馈已被现有资产吸收的输入生成报告；相应列表为空，空态说明本次没有足够证据支持建议或持久化。

### VAL-CAND-002
- **Behavior (行为)**: 报告明确区分不要求行动的洞察、用于低成本验证的“值得尝试”和会修改长期资产的沉淀候选，不让三种内容共享同一个默认采纳状态。
- **Tool (工具)**: manual
- **Evidence (判据)**: 代表性报告中的三类内容具有可辨识的标签和行动边界；洞察没有应用按钮，“值得尝试”只提供试用动作，长期候选需要单独人工选择且默认未选中。

### VAL-CAND-003
- **Behavior (行为)**: 只有用户明确要求长期保持某种行为，或同一纠正、约束、流程在至少两个独立会话中重复出现时，才允许提出长期沉淀候选。
- **Tool (工具)**: manual
- **Evidence (判据)**: 单次普通反馈不生成长期候选；明确的持久化指令可以生成候选；两个不同会话中的同类反馈可以生成候选，并列出各自证据。

### VAL-CAND-004
- **Behavior (行为)**: 已被现有资产完整吸收的反馈、一次性问题、没有行动权的外部问题和 `session-compound` 自身缺陷不会被包装成项目沉淀候选。
- **Tool (工具)**: manual
- **Evidence (判据)**: 分别提供四类代表性证据时，候选列表不包含对应条目；`session-compound` 自身缺陷可以作为报告限制或待修问题呈现，但不会伪装成被复盘项目的长期经验。

### VAL-CAND-005
- **Behavior (行为)**: 已经安装或频繁使用的能力不会被包装成“尚未尝试的新功能”；只有真实新增或安装技能的长期候选才触发生态搜索，搜索结果不能反向制造建议。
- **Tool (工具)**: repo-check
- **Evidence (判据)**: 当前能力清单中的既有能力只会以“新用法”出现并明确新增之处；无技能候选路径不执行生态搜索，有技能候选路径的搜索结果能够追溯到对应候选。

### VAL-EVAL-001
- **Behavior (行为)**: 单会话的指令遵循、技能召回和技能执行表现继续由独立新上下文评估；发现保留严重程度、置信度和证据，但不会自动一一转换为长期沉淀候选。
- **Tool (工具)**: manual
- **Evidence (判据)**: 同时包含正向发现、低置信度缺口、工具自身缺陷和真实重复模式的评估结果在评估区完整呈现；候选区只包含另行满足长期候选契约的条目。

### VAL-FLOW-001
- **Behavior (行为)**: `session-compound` 不自动安装技能或修改工程资产；洞察与“值得尝试”默认只留在报告中，长期候选默认未选中，只有用户明确选择后才交给对应的文档、技能或审查者管理能力。
- **Tool (工具)**: repo-check
- **Evidence (判据)**: 未选择候选时工程无变更；报告生成流程不存在默认应用动作，用户选择后的输出明确路由到对应能力而不在本技能中复制完整落库流程。
