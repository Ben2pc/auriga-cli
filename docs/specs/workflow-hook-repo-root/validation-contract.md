# Validation Contract — 钩子按工作区定位仓库（验收契约 — Hook repo-root resolution）

> 与 spec.md 配套：spec.md 描述 why + 用户可观察的 what；本文件描述什么算通过。
> 一条 VAL 不等于一个验证用例。

## Coverage map (覆盖矩阵)

| Range (范围) | VAL ids |
|---|---|
| 提交提醒 | VAL-REMINDER-001 |
| 就绪 / 合并守卫 | VAL-GUARD-001 ~ 002 |
| 宿主兼容 | VAL-COMPAT-001 ~ 002 |
| 失败语义 | VAL-SILENCE-001 |
| 发布身份 | VAL-VERSION-001 |

## Assertions (断言)

### VAL-REMINDER-001 — Cursor 形状下仍能提醒
- **验收要求**：进程目录不是 Git 仓库，标准输入带有指向超阈值脏仓库的 `workspace_roots` 时，提交提醒脚本打出含 `[commit-reminder]` 的附加上下文，并把冷却状态写进该仓库，而不是写进进程目录。
- **验证方式**：自动化测试
- **通过标准**：标准输出含 `[commit-reminder]` 与正确的行数 / 文件数；目标仓库出现状态文件；进程目录没有 `.git` 状态文件。

### VAL-GUARD-001 — 就绪守卫不因插件目录放行
- **验收要求**：进程目录不是 Git 仓库，标准输入带有指向含未清理就绪产物之仓库的工作区定位字段，且命令是 `gh pr ready` 时，守卫拦截。
- **验证方式**：自动化测试
- **通过标准**：退出码 2，标准错误说明该仓库里的就绪产物；不得退出码 0。

### VAL-GUARD-002 — 裸合并仍检查目标仓库的拉取请求
- **验收要求**：进程目录不是 Git 仓库，标准输入带有工作区定位字段，命令是不带编号或地址的 `gh pr merge` 时，守卫在目标仓库上下文中取正文；正文里验收标准或验证计划仍有未勾选项则拦截。
- **验证方式**：自动化测试
- **通过标准**：能稳定复现「定位到目标仓库后按正文拦截」；不得因为进程目录不是仓库就退出码 0。

### VAL-COMPAT-001 — 仅有会话目录时行为不变
- **验收要求**：标准输入没有工作区字段，进程目录就是超阈值脏仓库或含就绪产物的仓库时，提醒和就绪守卫与现在一样生效。
- **验证方式**：自动化测试
- **通过标准**：现有「在仓库目录里调用」的用例仍然通过。

### VAL-COMPAT-002 — Grok 定位字段同样生效
- **验收要求**：进程目录不是 Git 仓库时，`workspaceRoot` / `cwd`，或环境变量 `CLAUDE_PROJECT_DIR` / `GROK_WORKSPACE_ROOT`，任一指向目标仓库，提醒和就绪守卫仍按该仓库工作。
- **验证方式**：自动化测试
- **通过标准**：三种定位来源至少各有一条通过证据；驼峰 `toolInput` 仍能触发守卫。

### VAL-SILENCE-001 — 没有定位信号时保持静默
- **验收要求**：进程目录不是 Git 仓库，且载荷和环境变量都没有可用的工作区路径时，提交提醒不输出，就绪 / 合并守卫不拦截。
- **验证方式**：自动化测试
- **通过标准**：退出码 0，标准输出为空（提醒）或无拦截（守卫）。

### VAL-VERSION-001 — 插件版本对齐
- **验收要求**：`auriga-workflow` 根清单与三个宿主清单版本一致提升；命令行安装器版本不变。
- **验证方式**：仓库检查
- **通过标准**：四处 `version` 相同且高于 `4.0.26`；`package.json` 版本与改动前相同。
