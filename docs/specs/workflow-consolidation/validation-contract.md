# Validation Contract — 工作流组合收敛（验收契约 — 工作流组合收敛）

> 与 spec.md 配套：spec.md 描述 why + 用户可观察的 what；本文件描述什么算通过。
> 一条 VAL 不等于一个验证用例。

## Coverage map (覆盖矩阵)

| Range (范围) | VAL ids |
|---|---|
| 计划与快速流程 | VAL-PLANNING-001 ~ VAL-PLANNING-003 |
| 缺陷修复顺序 | VAL-DEBUGGING-001 ~ VAL-DEBUGGING-002 |
| 拉取请求生命周期 | VAL-LIFECYCLE-001 ~ VAL-LIFECYCLE-003 |
| 常驻上下文精简 | VAL-CONTEXT-001 ~ VAL-CONTEXT-004 |
| 范围与发布一致性 | VAL-PUBLICATION-001 ~ VAL-PUBLICATION-003 |

## Assertions (断言)

### VAL-PLANNING-001 — 计划载体保持二选一
- **验收要求**：需要计划的任务在进入实现前，由用户从内置 Plan 与 `planning-with-files` 中选择一种计划载体。
- **验证方式**：仓库契约测试与人工审阅。
- **通过标准**：中英文工作流明确表达两种计划载体互斥选择，且没有将 `goalify` 列为第三个互斥选项。

### VAL-PLANNING-002 — 自主执行可以组合
- **验收要求**：用户明确选择 `goalify` 时，可以在已选计划载体之上启动自主执行，而不是替代计划载体。
- **验证方式**：仓库契约测试与人工审阅。
- **通过标准**：工作流和 `goalify` 的关系说明一致表达“自主执行模式可与计划载体组合”。

### VAL-PLANNING-003 — 快速流程按语义分诊
- **验收要求**：快速流程只在任务是单一明确结果、没有未决产品或架构决定、无需跨会话跟踪且无需多个完整实施单元时跳过计划载体选择。
- **验证方式**：仓库契约测试。
- **通过标准**：中英文模板和 `spec-design` 交接不再使用模块数、验收标准数量或固定全量回归作为分诊条件。

### VAL-DEBUGGING-001 — 缺陷先确认根因
- **验收要求**：缺陷报告首先进入 `systematic-debugging`，在根因或问题证据尚未确认时不提前加载修复实现流程。
- **验证方式**：技能 frontmatter 与工作流契约测试。
- **通过标准**：常驻工作流明确先诊断，`test-driven-development` 的触发描述不再无条件覆盖尚未完成诊断的缺陷请求。

### VAL-DEBUGGING-002 — 修复阶段保留测试驱动
- **验收要求**：根因确认并进入修复实现后，仍使用 `test-driven-development` 建立有意义的失败证据和回归保护。
- **验证方式**：技能正文与工作流契约测试。
- **通过标准**：调试技能与测试技能之间存在明确顺序交接，且没有删除缺陷回归测试纪律。

### VAL-LIFECYCLE-001 — Ready 前继续询问资料去向
- **验收要求**：当前拉取请求的临时规格与计划在进入 Ready 前，继续由用户决定删除或归档。
- **验证方式**：模板、技能与 Hook 契约测试。
- **通过标准**：中英文工作流保留明确询问，`docs/specs/` Ready 门禁和跨拉取请求总规范例外保持有效。

### VAL-LIFECYCLE-002 — 合并后不固定打断
- **验收要求**：拉取请求合并后，不因常驻规则固定询问是否运行 `session-compound`。
- **验证方式**：模板契约测试。
- **通过标准**：中英文模板与仓库示例不包含合并后主动询问复盘的规则，`session-compound` 仍可由用户显式触发。

### VAL-LIFECYCLE-003 — 正式评审门禁保持
- **验收要求**：进入 Ready 后的首次正式评审仍通过 `deep-review`，后续执行遵循该技能自身授权规则。
- **验证方式**：模板和技能契约测试。
- **通过标准**：常驻入口保留 `deep-review` 路由，没有复制或削弱其输出协议与重跑门禁。

### VAL-CONTEXT-001 — 常驻入口只保留路由与不变量
- **验收要求**：`AGENTS.md` 受管区块不重复技能内部问题数量、步骤清单、豁免清单、输出格式或执行教学。
- **验证方式**：中英文模板差异审阅与仓库契约测试。
- **通过标准**：顶部工作流被收敛为必要路由，具体执行细节由对应技能维护。

### VAL-CONTEXT-002 — 文档目录仍可发现
- **验收要求**：文档目录表继续包含 `docs/rules/` 总入口以及各专属规则、临时规格、跨拉取请求规范、工作记录和稳定架构资料的路由。
- **验证方式**：仓库契约测试。
- **通过标准**：`docs/rules/` 行仍存在，`docs/ 其他` 泛化行被删除，其他有效目录生命周期保持一致。

### VAL-CONTEXT-003 — 熵增治理保留可执行含义
- **验收要求**：常驻原则继续指导评审发现的技术债务处置，在不扩大当前范围的前提下优先偿还确定、低风险的小额债务。
- **验证方式**：中英文模板人工审阅与契约测试。
- **通过标准**：模板保留持续对抗熵增原则，并明确它如何影响评审发现决策。

### VAL-CONTEXT-004 — 代理分发保留安全边界
- **验收要求**：代理分发仍明确原生代理优先、并行写入隔离、独立进程适用边界和派遣信息契约，但不固定模型型号或推理强度档位。
- **验证方式**：中英文模板与 `incremental-impl` 契约测试。
- **通过标准**：安全边界完整，固定 `xhigh`、`high`、`medium` 映射从常驻入口移除。

### VAL-PUBLICATION-001 — 双语与示例一致
- **验收要求**：中文模板、英文模板和仓库根示例 `AGENTS.md` 表达相同的工作流语义。
- **验证方式**：仓库契约测试与受管区块比较。
- **通过标准**：三处工作流版本、路由、目录和原则同步，无只更新单一语言的漂移。

### VAL-PUBLICATION-002 — 独立插件退出本轮清单
- **验收要求**：长期总规范将 `quality-gate-scaffolder` 及其 5 个 Scaffold 技能标记为本轮范围外，而不是待评审。
- **验证方式**：长期规范仓库检查。
- **通过标准**：评审索引和拆分总览都反映独立插件范围决定。

### VAL-PUBLICATION-003 — 用户可见版本同步
- **验收要求**：工作流模板、插件技能与发布清单采用一致的新版本，运行时内容固定点能够获取本次变更。
- **验证方式**：版本与发布契约测试、真实安装包端到端验证。
- **通过标准**：CLI 包版本、工作流版本、Auriga 插件双运行时清单和说明文件一致更新，安装结果包含新语义。
