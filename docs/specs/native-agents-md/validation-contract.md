## 2. 按产品分项组织断言

### 2.1 原生安装与安全升级

#### VAL-INSTALLATION-001 — 新安装只生成原生入口
- **验收要求**：在没有既有项目指令文件的目录安装 workflow 后，生成受管 `AGENTS.md`，且不生成 `CLAUDE.md`。
- **验证方式**：文件系统集成测试。
- **通过标准**：`AGENTS.md` 是带完整受管标记的真实文件，目录中不存在 `CLAUDE.md` 或备份文件。

#### VAL-MIGRATION-001 — Auriga 旧入口安全退场
- **验收要求**：升级当前 `CLAUDE.md -> AGENTS.md` 形态或更早的 `AGENTS.md -> CLAUDE.md` 形态后，工程自定义内容保留在 `AGENTS.md`，Auriga 管理的 `CLAUDE.md` 入口消失。
- **验证方式**：文件系统迁移测试。
- **通过标准**：两种旧形态都迁移为单一真实 `AGENTS.md`，无悬空软链，受管区块升级且用户区逐字保留。

#### VAL-SAFETY-001 — 用户 Claude 指令不被覆盖
- **验收要求**：项目已有真实 `CLAUDE.md` 或指向其他目标的软链时，workflow 安装不得修改、删除或备份替换它。
- **验证方式**：文件系统边界测试。
- **通过标准**：原文件字节或软链目标保持不变，安装器生成 / 升级 `AGENTS.md` 并输出 Claude Code 默认发现冲突的提示。

#### VAL-COMPATIBILITY-001 — 历史形态保持可识别可卸载
- **验收要求**：状态扫描仍识别旧版项目形态，卸载仍只删除 Auriga 管理的文件或精确软链。
- **验证方式**：现有状态扫描与卸载回归测试。
- **通过标准**：历史形态报告已安装；卸载后无 Auriga 遗留，用户自有文件和软链保持原样。

### 2.2 分层规范与兼容说明

#### VAL-DOCUMENTATION-001 — 活跃规范统一原生策略
- **验收要求**：中英文模板、文档管理技能、帮助与安装说明都把 `AGENTS.md` 描述为默认分层入口，不再要求每层保留兼容软链。
- **验证方式**：仓库契约测试与活跃文件反向搜索。
- **通过标准**：所有默认安装和分层规范表述一致，双语语义对应，历史记录之外没有相反的默认要求。

#### VAL-DOCUMENTATION-002 — 旧环境恢复路径可发现
- **验收要求**：用户能从安装说明得知 Claude Code 原生读取的最低版本和不可用场景，并找到显式兼容方法。
- **验证方式**：文档审查与链接检查。
- **通过标准**：README 或权威开发指南说明 2.1.277 门槛、第三方提供商 / 功能开关限制、`@AGENTS.md` 或软链兼容方式及验证方法。
