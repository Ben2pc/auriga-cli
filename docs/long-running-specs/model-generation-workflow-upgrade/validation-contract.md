## Assertions (断言)

### VAL-INVENTORY-001 — 评审索引覆盖全部范围内技能
- **验收要求**：所有 Auriga 自有技能和锁定的外部技能都能在评审索引中找到唯一记录；范围外插件只保留清单，不进入评审完成度。
- **验证方式**：仓库契约检查
- **通过标准**：评审索引与仓库清单双向比对后不存在遗漏项或无来源项。

### VAL-INVENTORY-002 — 每项资产具有明确归属
- **验收要求**：每项纳入范围的技能都明确标注维护权、安装路径、更新路径和目标运行时。
- **验证方式**：仓库契约检查
- **通过标准**：任一资产记录都能独立回答四项归属信息，且与仓库清单一致。

### VAL-REVIEW-001 — 深入评审必须有唯一处置结论
- **验收要求**：每项进入深入评审的技能都具有唯一的主处置结论，并附有针对目标模型的证据；用户明确按分发与触发边界保留的非强制工具型技能，可以记录范围理由、风险和重新评估条件后跳过深入评审。
- **验证方式**：人工审查
- **通过标准**：每份完成的深入评审记录包含结论、模型证据、风险和重新评估触发条件；每项跳过深入评审的保留决定明确区分默认安装与默认执行，并声明其不构成模型能力结论。

### VAL-REVIEW-002 — 保留约束必须证明其不可替代职责
- **验收要求**：被保留或内化的强制约束都能证明其职责不能稳定地交给目标模型原生完成；按范围决定保留的工具型技能只提供能力，不被表述为强制约束。
- **验证方式**：人工审查
- **通过标准**：深入评审记录展示可复现失效模式，或证明该约束属于确定性机制、持久契约、独立评估或跨运行时适配；跳过深入评审的记录证明该技能不会成为每个任务的强制步骤。

### VAL-REVIEW-003 — 精简与删除必须保留恢复条件
- **验收要求**：被删除或精简的约束都记录兼容风险和可逆的恢复条件。
- **验证方式**：人工审查
- **通过标准**：评审记录能说明受影响场景、观察信号和何时重新引入，而不是只写“模型更强”。

### VAL-MIGRATION-001 — 核心工作流不存在职责冲突
- **验收要求**：最终核心工作流不存在职责重复、循环触发或无上限代理派遣。
- **验证方式**：人工审查
- **通过标准**：组合审查能从入口到完成状态追踪所有触发关系，未发现同一职责由多项约束重复承担或形成递归。

### VAL-MIGRATION-002 — 双运行时边界明确且最小
- **验收要求**：保留的核心工作流在 Claude Code 与 Codex 中都具有明确且最小的运行时边界。
- **验证方式**：端到端安装验证与人工审查
- **通过标准**：两个运行时的安装结果与声明一致，运行时特有约束不会无条件施加到另一运行时。

### VAL-MIGRATION-003 — 用户可见变化同步发布资产
- **验收要求**：对用户可见的技能集合或安装行为发生变化时，发布版本与用户文档同步反映该变化。
- **验证方式**：仓库契约检查
- **通过标准**：发布版本、双语说明、目录清单和安装行为不存在相互矛盾。

### VAL-DOCUMENTATION-001 — 长期规范不受单个拉取请求清理阻塞
- **验收要求**：跨多个拉取请求的总规范可以在单个子拉取请求标记 Ready 时继续保留，不会被当前拉取请求的临时规范清理门禁阻塞。
- **验证方式**：仓库契约检查
- **通过标准**：工作流文档与门禁测试都明确区分 `docs/specs/` 和 `docs/long-running-specs/` 的生命周期。

### VAL-DOCUMENTATION-002 — 长期规范不能替代子拉取请求契约
- **验收要求**：长期总规范不能替代当前子拉取请求的独立验收契约，全部子拉取请求结束后由人工决定归档。
- **验证方式**：人工审查与仓库契约检查
- **通过标准**：工作流与 `spec-design` 同时要求当前子拉取请求使用 `docs/specs/`，并将长期规范的最终归档保留为人工决策。
