# goalify 评审

## 当前职责

`goalify` 只在用户明确选择自主运行时，把已澄清的需求或当前工作进展封装成边界清楚的目标。它定义权威事实、执行约束、终点、停止条件和交接，不预先替运行期编排实施步骤。

## 可复现失效模式

- 已有明确终点仍重复询问，增加无效交互。
- 把正式规格误当作强制前置条件，使快速流程无法自主执行。
- 固定默认分支、测试顺序或切片，覆盖当前分支和仓库工作流的真实状态。
- 自主运行跨过产品范围或架构人工确认门禁。
- 运行环境不支持直接启动目标时，仍声称已经操作 `/goal`。

## 目标模型证据

本轮没有执行 GPT 5.6 Sol 或 Fable 5 模型行为评测，不把技能精简解释为真实代理行为已经得到验证。当前证据来自用户实际使用反馈、人工审阅、文本契约测试、双运行时官方技能校验器和仓库完整测试。

## 与其他资产的关系

- `spec-design` 和对话中的已确认事实提供需求边界，正式规格是优先来源但不是必需条件。
- `arch-design` 保留人工确认门禁；自主目标不能自行批准新的实质性架构决定。
- `incremental-impl` 在实现阶段决定规模和切片，`goalify` 不预编实施步骤。
- `git-workflow`、`deep-review` 和仓库规则决定实际交付流程；目标只引用适用规则，不复制其教学。

## 处置结论

- 结论为精简，Auriga 继续拥有该技能。
- 主文件从 110 行压缩到 45 行，删除固定六段模板、冗长正反示例和重复的实现纪律。
- 目标契约收敛为目标、权威事实与约束、终点与停止条件、交接四部分。
- 保留 PR Ready、深度评审收敛、明确授权的合并和自定义终点；选择深度评审收敛即授权为达到收敛而重复评审。
- 保留架构人工确认门禁、临时规划资料的无人交互归档规则，以及 Codex 与 Claude Code 的条件式启动差异。

- 技能与插件质量无发现；模型行为评测仍是明确的本轮非目标。

- Claude Code 与 Codex 官方 `quick_validate.py` 均通过。

## 风险与恢复条件

- **风险：精简删除了必要边界。** 若实际运行重新出现重复询问、无授权跨阶段或固定错误实施路径，优先补回最小决策规则，不恢复整套教学。
- **风险：文本契约不能证明模型行为。** 若终点或架构门禁在真实任务中不稳定，再为 Claude Code 与 Codex 增加代表性行为评测。
- **风险：深度评审收敛造成高成本循环。** 若重复评审长期不收敛或消耗失控，应增加用户可见的停止信号或重新评估该内置终点。
