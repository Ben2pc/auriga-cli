# 取消自动技能迁移 — Spec

> PR #178 的最终决策记录。原方案尝试自动清理已内化到 `auriga-workflow` 的旧独立技能；正式评审证明其复杂度和误删风险超过小团队收益，因此改为删除自动迁移机制。

## Why

Auriga 目前只有 2–3 名内部使用者。升级后口头通知、确认插件技能生效并手动删除旧副本的成本很低；自动迁移却必须处理两个运行时、项目级与用户级作用域、软链接、锁来源、本地修改、并发写入和崩溃恢复。继续维护这套状态机不符合“如无必要，勿增实体”的原则。

## Requirements

1. 安装或升级 `auriga-workflow` 不得扫描、修改或删除 `.claude/skills`、`.agents/skills` 以及 skills 锁文件。
2. 删除仅服务于工作流技能自动迁移的来源判定、内容散列、插件载荷验证、软链接物化、迁移锁、恢复日志和清理代码。
3. 删除对应的迁移安全测试与复杂端到端拓扑；保留一条回归测试证明插件安装不会修改旧独立技能和锁文件。
4. 双语说明明确采用人工清理：确认插件技能可用后，使用 `npx skills remove <skill-name>` 或人工方式清理旧副本；内部团队直接通知。
5. `systematic-debugging` 的插件内实现、父子验收追踪，以及“GPT 5.6 Sol / Fable 5 模型评测未执行”的状态保持不变。

## Acceptance criteria

- `src/plugins.ts` 不再包含工作流技能自动迁移入口或辅助状态机。
- 安装 `auriga-workflow` 后，预先存在的独立技能正文和锁文件逐字节不变。
- `auriga-notify` 自身既有的配置迁移不受影响。
- README、ADR、开发者指南和长期总规范不再承诺自动技能迁移。
- 模型评测不属于本 PR。

## Non-goals

- 不提供迁移命令、清理脚本、警告或兼容层。
- 不自动判断哪些旧副本可以删除。
- 不修改 `systematic-debugging` 技能正文。
