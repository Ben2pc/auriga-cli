# Reviewer Creator Modernization — Review (项目审查者创建技能现代化 — 评审)

## Conclusion (结论)

主结论：**精简**。

`reviewer-creator` 继续保留。它承担项目审查者的持久格式、调度定位和验证协议，不能只靠模型临场发挥；但固定篇幅、强制提问和与 `deep-review` 重复的注册表应删除。

## Failure Mode (失效模式)

- 项目规则被写成无法被 `deep-review` 机械发现或调度的自由文本。
- 补充型审查者缺少明确宿主，导致重复派发、漏发或来源含糊。
- 项目审查者只写抽象最佳实践，缺少能产生有证据发现的判断边界。
- 创建技能与调度器分别维护内置名称和触发条件，协议升级后发生漂移。

## Model Generation Assessment (新模型判断)

GPT 5.6 Sol 与 Fable 5 已能根据明确项目规则撰写审查问题、选择工具并自行控制篇幅，因此不再需要固定问题数量、固定场景数量或无条件先问用户。它们仍不能凭通用能力可靠推断 Auriga 私有的 frontmatter、`extends`、触发标签和宿主输出契约，这些机械协议必须保留。

本轮未执行模型评测；结论来自协议职责和当前技能文本审查。

## Retained Contracts (保留契约)

- 项目审查者写入仓库或最近适用作用域的 `docs/rules/review/`。
- `extends` 必须显式指向当前内置审查者或 `standalone`，不做正文语义猜测。
- 补充型审查者继承宿主输出契约；独立型审查者保留完整输出契约。
- frontmatter、工具权限、规则来源和项目协议验证继续作为完成门禁。
- 边界容易混淆时仍使用应报告或不应报告场景帮助较低档审查模型判断。

## Removed Constraints (删除约束)

- 固定数量的检查问题和场景。
- 无论证据是否明确都先询问用户定位。
- 在创建技能中复制全部内置审查者和触发标签。

## Cost and Recovery Signal (成本与恢复信号)

精简后减少常驻上下文、一次不必要交互和双份注册表维护。若后续发现项目审查者持续缺少关键边界、工作马模型无法稳定形成可执行检查，或条件式场景明显不足，再基于真实失败恢复更具体的模板提示，不恢复固定数量。
