# Validation Contract — Spec Design Modernization（验收契约 — 需求规格技能现代化）

> 与 spec.md 配套：spec.md 描述 why + 用户可观察的 what；本文件描述什么算通过。
> 一条 VAL 是一项验收断言，不代表只有一个验证用例。

## Assertions (断言)

### VAL-VALUE-001 — 先判断需求是否值得投入
- **验收要求**：`spec-design` 在详细澄清前先基于可获得事实帮助用户判断需求价值，不默认把每个想法加工成实现规格。
- **验证方式**：仓库契约检查
- **通过标准**：技能明确要求先调查证据，再进入价值门禁；“不做”是合法完成状态。

### VAL-VALUE-002 — 价值讨论必须有界且提供建议
- **验收要求**：价值门禁默认一个问题、最多两个问题，每个问题都包含推荐答案、理由和成本更低的替代思路。
- **验证方式**：仓库契约检查
- **通过标准**：技能不允许价值讨论超过两轮，也不允许只提问而不给判断支持。

### VAL-VALUE-003 — 价值门禁必须落到明确出口
- **验收要求**：价值门禁只能进入值得做、先验证、暂缓或不做四个出口；证据不足时不能默认进入完整实现。
- **验证方式**：仓库契约检查
- **通过标准**：每个出口有明确后续动作，“先验证”包含继续信号和停止信号。

### VAL-ALIGNMENT-001 — 需求清晰度必须建立在调查事实之上
- **验收要求**：需求是否明确以调查事实和可检查的对齐条件判断，不使用模型置信度、记忆印象或固定问题数量代替证据。
- **验证方式**：仓库契约检查
- **通过标准**：技能要求读取相关代码、行为、接口、测试、规则和用户资料，并删除约 95% 置信度与十轮停止点。

### VAL-ALIGNMENT-002 — 可查事实由 Agent 主动调查
- **验收要求**：能从环境查明的事实由 Agent 调查，只有事实无法决定的目标、范围、产品语义和取舍交给用户。
- **验证方式**：人工审查
- **通过标准**：技能清楚区分事实与决定，问题必须锚定调查事实并提供推荐答案与后果。

### VAL-ALIGNMENT-003 — 沿真实决策分支逐项对齐目标
- **验收要求**：存在会改变最终用户结果的决策树时，Agent 沿依赖关系一次解决一个决定，并检查答案是否仍与原始目标一致。
- **验证方式**：人工审查
- **通过标准**：技能保留苏格拉底式追问，但不强制为不存在的决策制造问题或候选。

### VAL-ALIGNMENT-004 — 实现前必须取得共同理解确认
- **验收要求**：用户确认共同理解前不能进入架构、计划或实现；实现中发现新的产品歧义时允许返回需求澄清。
- **验证方式**：仓库契约检查
- **通过标准**：技能具有明确人工确认门禁，且不再禁止实现开始后重新打开权威规格。

### VAL-SPECIFICATION-001 — 规格载体由追溯和交接需要决定
- **验收要求**：快速开发流程中的明确一句话需求可以由当前对话确认成为权威规格；非平凡、需追溯或需交接的需求默认写入文件。
- **验证方式**：仓库契约检查
- **通过标准**：技能列出文件化规格的客观触发条件，并与 `spec-conformance` 的权威来源优先级一致。

### VAL-SPECIFICATION-002 — 文件化规格只保存确认结果
- **验收要求**：文件化规格只记录确认后的价值、行为和决定，`spec.md` 的 Why 包含问题证据、为什么现在做、预期结果和更小替代方案。
- **验证方式**：仓库契约检查
- **通过标准**：模板不保存逐题问答流水，也不把 Why 降为背景介绍。

### VAL-VALIDATION-001 — 验收断言不等同于测试用例
- **验收要求**：每条 VAL 表示一项验收断言而非单个测试用例，只保留验收要求、验证方式和通过标准，不强制具体工具链表或测试实现。
- **验证方式**：仓库契约检查
- **通过标准**：技能、验收模板与测试驱动开发的消费契约一致，具体测试设施由测试阶段调查。

### VAL-DECOMPOSITION-001 — 只按完整用户结果拆分需求
- **验收要求**：需求只按可独立确认、独立验收且不误导总体目标的完整用户结果拆分，不使用固定数量门槛或实施策略决定子规范。
- **验证方式**：仓库契约检查
- **通过标准**：技能和 umbrella 模板删除固定规模阈值与抽象分支等实施轴，保留父子 VAL 覆盖关系。

### VAL-LIFECYCLE-001 — 长期规范不能替代子拉取请求契约
- **验收要求**：跨拉取请求总规范继续保留共同契约与状态，每个子拉取请求仍有独立规格、验收和 Ready 生命周期。
- **验证方式**：仓库契约检查
- **通过标准**：`docs/long-running-specs/` 不能替代 `docs/specs/<child-topic>/`，父子 VAL 可追溯。

### VAL-LIFECYCLE-002 — 外部资料读取遵循运行时能力
- **验收要求**：技能在 Claude Code 与 Codex 中按可用能力读取 Figma、网页和外部文档，不把某一运行时的工具限制写成通用禁令。
- **验证方式**：人工审查
- **通过标准**：技能采用能力检测与安全降级描述，双运行时插件清单保持一致且用户可见说明同步。

### VAL-RECOVERY-001 — 精简必须保留恢复条件
- **验收要求**：精简记录受影响场景和恢复条件；若价值门禁误拦必做事项、追问持续遗漏关键产品分支，或口头规格造成可追溯性缺口，可以基于真实失败恢复更强约束。
- **验证方式**：人工审查
- **通过标准**：正式评审记录点名观察信号和局部恢复方式，不以“模型更强”作为唯一理由。
