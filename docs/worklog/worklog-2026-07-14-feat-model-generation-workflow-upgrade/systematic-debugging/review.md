# systematic-debugging 评审

## 当前职责

在实施永久修复前约束根因判断必须有证据，并为可复现问题、低频线上问题和生产事故提供一致的诊断边界。

## 可复现失效模式

- 看到错误后直接修改最可疑的代码，没有验证路径证明修改覆盖了用户症状。
- 线上问题暂时无法复现时，把推测写成已确认根因。
- 生产事故只顾调查而延误恢复，或把回滚、关闭开关等临时缓解描述为永久修复。
- 添加大量与问题无关的日志或浅层测试，既不能缩小根因，也不能捕获真实回归。

## 目标模型证据

本轮没有执行目标模型评测，也没有把社区观点当作目标模型的受控评测结论。用户提供的新模型使用反馈和对现有技能的逐条审查支持一个暂定方向：目标模型已经能自行选择常见诊断工具，固定四阶段、强制最小复现、固定假设数量和级联技能调用可能重复模型能力；但“根因结论必须对应验证或证据采集路径”仍是跨模型、跨运行时的稳定工程契约。

后续若建立模型评测基线，应继续验证这一结论，不把本次人工评审冒充为长期模型能力证明。

## 与其他资产的关系

- `test-driven-development` 负责实现阶段的红—绿—重构，不替代问题现场与根因证据。
- `verification-before-completion` 负责完成声明前的证据，不替代修复前的诊断判断。
- `incremental-impl` 只在实现切片发生回归时触发本技能，不形成强制级联。

## 处置结论

**暂定内化。** 保留 `systematic-debugging` 名称和证据优先原则，将其缩减为 Auriga 自有的自适应调试契约，并通过 `auriga-workflow` 同时发布给 Claude Code 和 Codex。实现已合入 PR #177；迁移安全由 PR #178 加固。模型评测未执行且不在 PR #178 范围内，因此本记录不把暂定处置结论表述为父级模型验收已通过。

## 风险与恢复条件

- 风险：约束过轻时，模型可能在证据不足时过早结束调查。恢复信号是多次出现无法由当前契约拦住的猜测式修复。
- 风险：内化后需要 Auriga 主动吸收上游的新方法。恢复信号是上游出现经过验证、明显优于当前工具箱的诊断契约。
- 风险：旧独立副本可能遮蔽插件版本。迁移只清理由历史官方来源锁记录证明为受管资产的副本，避免误删同名自定义技能；测试与真实安装验证覆盖项目级、用户级和单运行时迁移。
