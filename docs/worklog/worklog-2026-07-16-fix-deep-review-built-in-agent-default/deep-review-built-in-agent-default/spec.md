# 深入评审默认使用内置 Agent

## 背景

`deep-review` 同时写了“优先使用平台内置子代理”和“平台能力确有需要时调用外部代理”，又把运行时缺少细粒度工具限制定义成停止分派条件。这会让编排器在用户没有要求时改用独立进程，偏离团队的默认执行方式。

## 目标行为

- 正式评审默认使用平台内置、干净上下文的 Agent。
- 只有用户明确要求独立进程的非交互式 Agent 调用时，才允许使用外部 Agent。
- 缺少逐 Agent 的细粒度工具允许列表时，继续使用平台原生隔离、权限边界和只读任务契约，不切换外部进程，也不停止内置评审。
- 用户明确要求外部调用时，外部进程必须具备可执行的只读边界；无法保证时不启动，并记录审查缺口。

## 非目标

- 不改变审查维度、路由信号、审查者内容或综合格式。
- 不改变不可信头分支的执行限制。
