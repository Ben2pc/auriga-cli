# 交付验证记录 — Spec（规范）

## 1. Product Overview / 产品总览

当前流程要求验证后才能声明完成，但验证事实分散在工具输出和对话中。增加与验收契约配套的结果文件，让执行者及时留存证据，评审者可追溯，用户能直接看见验证范围和缺口。

来源为本任务用户已确认的方案及后续收窄：记录有明确验收目的的交付验证活动，不记录测试驱动开发的逐次试跑。无项目专属规格或测试规则。

## 2. Product Requirement Details / 产品需求分项

### 2.1 留存交付验证事实

- **原始产品需求**：配套创建验证结果，每完成一个有效验证就记录，允许契约外的额外验证。
- **用户可感知行为**：文件化规格初始化结果及未执行覆盖；执行者记录实施单元、整体验收或额外验证的对象、执行、实际结果和证据。失败与阻塞也保留，复验可追溯。
- **范围边界**：不逐次记录预期失败、局部试跑、调试探针；不把结果当成新的需求来源。
- **验收映射**：VAL-RECORDING-001。

### 2.2 判断当前是否完成

- **原始产品需求**：完成后同步用户完成了哪些验证。
- **用户可感知行为**：覆盖所有当前要求，相关改动后标为待复验；完成摘要直接说明验证、实际结果、未完成或受限项目及影响，并提供记录链接。无文件化规格的小任务仍给摘要。
- **范围边界**：命令成功不等于需求通过；不允许用旧通过、额外构建结果或文件链接掩盖验收缺口。
- **验收映射**：VAL-HANDOFF-001。

### 2.3 交接与归档

- **原始产品需求**：结果文件与现有需求设计、执行和收尾工作流连通。
- **用户可感知行为**：各子规范保留结果，跨规范验收按需留证；记录按当前拉取请求归档，保持契约、总规范和证据引用可追溯。三个安装宿主得到相同规则，双语工作流一致。
- **范围边界**：不新增独立技能或运行时强制校验器；用户后续授权修复评审冲突、合并并按标准标签流程发布。
- **验收映射**：VAL-LIFECYCLE-001。
