# test-driven-development 与 test-designer 合并评审

## 当前职责

在改变可观察行为时，选择有意义的测试接缝、建立原因正确的失败证据，并以最小纵向切片完成实现与回归验证。

## 可复现失效模式

- 代理为了满足流程而增加只匹配说明文字、提示词措辞或内部调用顺序的测试。
- 外部测试驱动开发技能与 `test-designer` 重复约束同一阶段，增加上下文、流程开销和低价值用例。
- 先出现实现时机械删除可用代码，或在重构中人为制造红灯，而不是先建立行为保护网。
- 测试过度依赖模拟和实现细节，无法证明公共接口上的真实行为。

## 目标模型证据

本轮没有执行 GPT 5.6 Sol 或 Fable 5 的受控评测。用户使用经验表明，新模型已经具备基础测试驱动开发能力，而旧组合会诱导无意义测试；对 Superpowers、原 `test-designer` 与 Matt Pocock 版本的职责对照也证明两项资产存在明显重叠。这些证据足以支持当前工程处置，但不冒充父级规范要求的目标模型评测结论。

## 与其他资产的关系

- `spec-design` 提供验收契约和验证工具事实；本技能决定当前切片的具体测试接缝。
- `verification-before-completion` 在完成声明前扩大验证范围，不重复红绿循环。
- `deep-review` 的测试质量审查在拉取请求阶段发现遗漏，不复制编码阶段的红绿循环。
- `incremental-impl` 负责切片与提交边界，本技能负责每个行为切片内部的测试证据。

## 处置结论

**精简、内化并合并。** Auriga 发布一个不超过 80 行的自有 `test-driven-development` 技能，吸收原 `test-designer` 中验收契约、项目测试规则、行为测试和模拟边界的有效部分。外部 Superpowers 同名技能退出锁定与预设，`test-designer` 删除。

## 风险与恢复条件

- 风险：约束过轻后，代理可能跳过能有效捕获缺陷的失败测试。若正式评审连续发现“实现正确但缺少关键回归证据”，再补充最小触发规则。
- 风险：精简测试设计约束后可能遗漏复杂边界。若复杂功能反复出现同类盲区，应优先加强项目级 `docs/rules/test/` 或事后测试质量审查。
- 风险：旧独立副本可能遮蔽插件版本。团队确认插件技能生效后人工删除；安装器不自动扫描、修改或迁移技能目录与锁文件。
- 恢复原外部技能的条件：自有技能无法以较低上下文成本约束已被证实的重复失效，且上游版本提供可验证的净收益。

## 当前状态

- 模型评测未执行，不在当前子项范围内。

## 第二轮正式评审结论

评审覆盖规范一致性、正确性、文档同步、健壮性、架构、测试质量、代码质量与技能插件质量。正确性和架构维度无发现；全部发现及后续处理保留如下：

| 发现 | 严重度 / 置信度 | 处理 |
|---|---|---|
| 双语 README 仍把测试驱动开发列为外部技能 | 阻断 / 高 | 已修复为插件内技能 |
| 历史设计快照仍展示 v1.0 的独立技能目录与安装流程 | 阻断 / 高 | 不修改；文件首段明确声明是 v1.0 历史快照，并指向当前权威文档，改写会破坏历史语义 |
| 旧命令提示默认只安装 Claude Code，且未说明旧副本遮蔽风险 | 阻断 / 高 | 已改为显式 `--agent both`，并提示确认生效后人工删除旧副本 |
| 技能与说明对默认模型行为的约束归属不一致 | 阻断 / 高 | 后续用户澄清认定该行为不应成为产品承诺，已从最终契约和产品表面移除 |
| 工作流对上述默认行为的回归断言覆盖不足 | 阻断 / 高 | 原断言随产品承诺撤销；改为防止冗余执行归属说明回归 |
| 新技能对删除重来的防回归正则存在漏检 | 阻断 / 高 | 已补充对破坏性重来规则的回归断言 |
| 迁移辅助函数与测试名称把“已退役”混称为“已迁移” | 非阻断 / 高 | 已统一为“插件替代或退役入口”语义 |
| 预设测试注释仍写 4 个外部技能 | 非阻断 / 高 | 已修正为 3 个 |
| 长期规范仍称 Superpowers 提供两个当前核心外部技能 | 非阻断 / 高 | 已区分当前外部依赖与历史来源 |
| 退役引用检查漏掉会话复盘技能及其评估协议 | 非阻断 / 高 | 已加入检查范围 |
| 插件目录测试未锁定统一入口描述 | 非阻断 / 高 | 已断言目录描述包含 `test-driven-development` 且不含 `test-designer` |
| 新技能自动触发与豁免条件未被测试锁定 | 非阻断 / 高 | 已覆盖功能、缺陷修复、重构及四类豁免条件 |
| 技能插件审查者的两条通用官方规则可能过时 | 非阻断 / 高 | 不处理；该审查者文件不在本拉取请求差异内，另行评审以避免扩大当前技能迁移范围 |
