# Incremental Impl 技能精简规格

## 目标

把 `incremental-impl` 从实施阶段百科全书精简为需求改动拆分技能：先把已确认方案拆成完整、可验证、可集成的实施单元，再按依赖增量落地。多写者派发只是拆分完成后的可选执行方式。

## 已确认行为

- 消费已经确认的需求、架构设计和计划，不在实现阶段重新决定产品范围、模块边界或迁移形态。
- 完整实施单元独立交付一个连贯需求结果或合法迁移状态，包含结果成立所需的实现、行为保护和必要配套变化。
- 单元边界来自需求结果、技术不变量、验证和合法中间状态，不来自文件数、代码行数、提交或写入者。
- 必须同时生效的改动留在同一单元；只有能分别验收、分别集成的结果才拆开。
- 删除 XS～XL 分档、差异行数阈值、最低代理数量和固定切片大小。
- 默认单写者；只有文件所有权、输入输出和依赖边界独立时才并行。
- 保留可选的模型与推理强度覆盖，默认继承运行环境，不写死具体型号。
- 并行写者必须隔离；优先使用运行时原生工作树派发，不支持时由主代理预建，无法隔离则串行。
- 代理间通信可以用于协调，但权威状态必须能从仓库或持久计划验证。
- 派发数据包保留目标、事实来源、所有权、依赖、验证和输出证据。
- 子代理使用精简交接；主代理内联实现不生成固定交接模板。
- 提交、测试驱动开发、调试和完成声明分别沿用现有工作流，不在本技能重复教学。

## 非目标

- 不移除并行写入能力。
- 不限制 Claude Code、Codex 或未来运行时可提供的模型、推理强度、工作树和通信参数。
- 不执行模型行为评测。
