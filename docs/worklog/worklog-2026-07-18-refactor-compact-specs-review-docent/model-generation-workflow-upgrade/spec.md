# 新一代模型工作流升级（完成态归档）

> 面向 GPT 5.6 Sol 与 Fable 5 的工作流重构已经完成。本文件合并原总规范、15 组子规格与验收契约，只保留仍需跨会话查询的最终职责、行为边界、风险和证据入口。

## 当前状态

- 13 个 Auriga 核心工作流技能已逐项处理，组合工作流已在 PR #195 收敛。
- `quality-gate-scaffolder` 及其 5 个脚手架技能、其他插件和可选能力不在本轮范围。
- 本轮没有执行 GPT 5.6 Sol 或 Fable 5 的统一模型评测。处置结论来自实际使用反馈、代码与机制边界、产物价值和维护成本，不能引用为模型能力基准。
- 子规格与验收契约只服务实施期确认，完成后已压缩进本文件并删除；正式评审记录继续作为历史理由、风险与恢复条件的证据。
- 本文件不维护父子验收编号、逐项测试结果或发布补丁版本。当前行为以技能、工作流模板、插件清单和确定性机制为准。

## 共同结论

1. 工作流只保留产品语义、人工确认、持久契约、独立评估和确定性机制无法稳定替代的职责，不用固定仪式补偿旧模型能力。
2. 默认安装不等于默认执行。显式工具型技能可以保留，但不能变成每个任务的强制步骤。
3. 需求规格、架构设计、实施单元、测试证据、正式评审和 Git 生命周期各自负责一个边界，避免重复触发与循环派遣。
4. Claude Code 与 Codex 共用行为契约；运行时差异使用最小适配，不扩散成所有运行时的负担。
5. 当前事实留在技能、工作流模板和确定性机制中；本目录只保存完成态决策与历史证据入口。

## 跨技能与修复型决定

| 决定 | 完成态契约 | 证据 |
|---|---|---|
| 删除 `verification-before-completion` | 完成声明是一条常驻状态规则，不是按需加载的专业技能：任何完成、修复、通过或可评审判断都必须来自最后一次相关修改之后且与声明匹配的验证；证据不足时说明缺口。测试驱动开发、增量实现、就绪门禁和持续集成继续承担各自职责，不复制新的替代流程。 | PR #181；[评审记录](../../worklog-2026-07-14-refactor-remove-verification-skill/verification-before-completion/review.md) |
| 取消自动技能迁移 | 安装或升级插件不得扫描、修改或删除用户已有独立技能和锁文件。删除来源判定、内容散列、迁移锁、恢复日志等状态机；团队先确认插件技能可用，再通过 `npx skills remove <skill-name>` 或人工方式清理旧副本。 | PR #178 |
| 深度评审默认内置 Agent | 正式评审默认使用平台内置、干净上下文的 Agent；缺少逐 Agent 工具白名单时仍使用平台权限和只读任务边界。只有用户明确要求非交互式外部进程时才切换，无法保证只读边界时不启动并报告缺口。 | 深度评审后续修复记录 |
| 工作流组合收敛 | 需要计划时在内置计划与文件计划之间选择；自主目标可与二者组合但不替代人工架构确认。快速流程按是否存在单一明确结果、未决决定、跨会话跟踪或多个实施单元判断，不使用固定规模阈值。测试、验证、评审和 Git 生命周期继续按各自适用边界执行。 | PR #195 |

## 后续复核条件

只有出现以下情况才重新打开对应技能的设计，而不是恢复整套旧流程：

- 技能开始自动触发、成为每个任务的强制步骤，或明显增加无关上下文与交互成本。
- 精简后持续遗漏同一类重要风险、人工确认或可追溯证据。
- Claude Code、Codex 或目标模型的工具、子代理、插件和校验能力发生实质变化。
- 外部资产职责或维护权变化，导致核心路径重新依赖不可控行为。

具体历史理由、已知风险和局部恢复条件以表格链接的正式评审记录为准。
