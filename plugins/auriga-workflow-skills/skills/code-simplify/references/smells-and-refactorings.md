# 坏味道目录与重构手法目录

`code-simplify` 主文档的「快速识别表」只列了最常撞见的几种坏味道。这份参考是完整目录——对齐《重构》(Martin Fowler)的坏味道清单和重构手法。

- **识别**坏味道,不确定该用什么手法时 → 查「第一部分」。
- 知道要做哪个手法,想确认它的意图 → 查「第二部分」。

重构手法名沿用《重构》中译本的译名,英文原名附在括号里,方便对照原书查具体步骤。

---

## 第一部分:坏味道完整目录

每条:**信号**(怎么认出它)+ **对应手法**(查第二部分)。

### A. 命名与体量

| 坏味道 | 信号 | 对应手法 |
|---|---|---|
| 神秘命名 | 名字没说清意图,得读实现才懂 | 改变函数声明、变量改名、字段改名 |
| 过长函数 | 函数太长,多个职责挤在一起 | 提炼函数;条件多用分解条件表达式;循环多用拆分循环 |
| 过长参数列表 | 参数一长串,记不住、容易传错 | 引入参数对象、保持对象完整、移除标记参数 |
| 过大的类 | 一个类字段、方法太多,什么都管 | 提炼类、提炼超类、以子类取代类型码 |
| 冗赘的元素 | 一个类 / 函数没承担够它的存在成本 | 内联函数、内联类、折叠继承体系 |
| 注释 | 注释在替糟糕的代码道歉 | 提炼函数、改变函数声明、引入断言(注释解释"为什么"时保留) |

### B. 重复与多余的抽象

| 坏味道 | 信号 | 对应手法 |
|---|---|---|
| 重复代码 | 同样的结构出现在多处 | 提炼函数、移动语句、函数上移 |
| 重复的 switch | 同一套 switch / if 分支散在多处,加一种就要全改 | 以多态取代条件 |
| 夸夸其谈通用性 | 为想象中的需求留的钩子、抽象、参数 | 折叠继承体系、内联函数、内联类、改变函数声明 |
| 中间人 | 一个类大半方法只是转发给别人 | 移除中间人、以委托取代子类 |

### C. 数据问题

| 坏味道 | 信号 | 对应手法 |
|---|---|---|
| 全局数据 | 全局可变状态,谁都能改,改坏了难定位 | 封装变量 |
| 可变数据 | 数据被多处改,出乎意料 | 封装变量、拆分变量、将查询与修改分离、以查询取代派生变量 |
| 基本类型偏执 | 用 string / number 表示本该有类型的概念(钱、坐标、区间) | 以对象取代基本类型、引入特例、以子类取代类型码 |
| 数据泥团 | 同几个字段总是一起出现 | 提炼类、引入参数对象、保持对象完整 |
| 临时字段 | 字段只在某些情况下有值,其它时候是空 | 提炼类、搬移函数、引入特例 |
| 纯数据类 | 只有字段和取值 / 设值,没有行为 | 封装记录、把操作它数据的函数搬进来、移除设值函数 |

### D. 变化轴与耦合

| 坏味道 | 信号 | 对应手法 |
|---|---|---|
| 发散式变化 | 一个模块因为多种不同原因被改 | 拆分阶段、搬移函数、提炼函数、提炼类 |
| 霰弹式修改 | 一个改动要同时动很多地方 | 搬移函数、搬移字段、函数组合成类、内联函数、内联类 |
| 依恋情结 | 一个函数总在操作别的模块的数据 | 搬移函数、提炼函数 |
| 过长的消息链 | `a.b().c().d()` 一长串,调用方耦合到中间结构 | 隐藏委托关系、提炼函数 + 搬移函数 |
| 内幕交易 | 模块之间私下交换太多内部信息 | 搬移函数、搬移字段、隐藏委托关系、以委托取代子类 |
| 循环语句 | 命令式循环,意图被埋在样板里 | 以管道取代循环 |

> 发散式变化、霰弹式修改、依恋情结是"边界没对齐变化轴"的信号。如果它们出现在**模块级**(模块边界画错了),那是 `arch-design` 的高度;函数 / 类**内部**的同名问题才留在这个 skill 里处理。

### E. 继承问题

| 坏味道 | 信号 | 对应手法 |
|---|---|---|
| 拒绝继承 | 子类用不上父类给的大部分东西 | 函数下移、字段下移、以委托取代子类 |
| 异曲同工的类 | 两个类做的事像,接口却不一样 | 改变函数声明、搬移函数、提炼超类 |

## 第二部分:重构手法目录

按《重构》的章节分类。标 **【大】** 的手法会**改变代码的形状**(多出 / 合并一个类、把分支结构换成多态)——见本节末尾的说明。

### 最基础的手法

| 手法 | 做什么 |
|---|---|
| 提炼函数 (Extract Function) | 把一段代码抽成一个有名字的函数 |
| 内联函数 (Inline Function) | 函数体很直白时,把它塞回调用处 |
| 提炼变量 (Extract Variable) | 给一个表达式起个解释性的名字 |
| 内联变量 (Inline Variable) | 变量名没比表达式本身多说什么时,去掉它 |
| 改变函数声明 (Change Function Declaration) | 改函数名或参数 |
| 封装变量 (Encapsulate Variable) | 给数据加一层访问函数,集中控制 |
| 变量改名 (Rename Variable) | 起个说清意图的名字 |
| 引入参数对象 (Introduce Parameter Object) | 把总一起出现的参数打包成对象 |
| 函数组合成类 (Combine Functions into Class) **【大】** | 一组操作同一份数据的函数收进一个类 |
| 函数组合成变换 (Combine Functions into Transform) **【大】** | 一组派生计算收进一个变换函数 |
| 拆分阶段 (Split Phase) **【大】** | 把做两件事的代码拆成顺序两段 |

### 封装

| 手法 | 做什么 |
|---|---|
| 封装记录 (Encapsulate Record) | 裸记录换成类 |
| 封装集合 (Encapsulate Collection) | 不直接暴露集合,提供增删的方法 |
| 以对象取代基本类型 (Replace Primitive with Object) | 给有意义的值一个类型 |
| 以查询取代临时变量 (Replace Temp with Query) | 临时变量换成函数 |
| 提炼类 (Extract Class) **【大】** | 一个类做太多,拆出一个新类 |
| 内联类 (Inline Class) **【大】** | 一个类没干够它的活,塞回别的类 |
| 隐藏委托关系 (Hide Delegate) | 不让调用方穿过中间对象 |
| 移除中间人 (Remove Middle Man) | 中间人没价值时,直接打交道 |
| 替换算法 (Substitute Algorithm) | 整段算法换成更清楚的 |

### 搬移特性

| 手法 | 做什么 |
|---|---|
| 搬移函数 (Move Function) | 函数挪到它该待的模块 |
| 搬移字段 (Move Field) | 字段挪到它该待的类 |
| 搬移语句到函数 / 到调用者 (Move Statements into/to Callers) | 重复或错位的语句搬到对的位置 |
| 以函数调用取代内联代码 (Replace Inline Code with Function Call) | 内联代码换成现成的函数 |
| 移动语句 (Slide Statements) | 把相关的语句挪到一起 |
| 拆分循环 (Split Loop) | 一个循环做两件事,拆成两个 |
| 以管道取代循环 (Replace Loop with Pipeline) | 命令式循环换成 map / filter 这类管道 |
| 移除死代码 (Remove Dead Code) | 删掉不再用的代码 |

### 重新组织数据

| 手法 | 做什么 |
|---|---|
| 拆分变量 (Split Variable) | 一个变量担了多个职责,拆开 |
| 字段改名 (Rename Field) | 起个说清意图的字段名 |
| 以查询取代派生变量 (Replace Derived Variable with Query) | 能算出来的就别存 |
| 改引用为值 / 改值为引用 (Change Reference to Value / Value to Reference) | 按是否需要共享身份来选 |

### 简化条件逻辑

| 手法 | 做什么 |
|---|---|
| 分解条件表达式 (Decompose Conditional) | 复杂条件和分支各自提炼成有名字的函数 |
| 合并条件表达式 (Consolidate Conditional Expression) | 几个结果相同的条件合并成一个 |
| 以守卫语句取代嵌套条件 (Replace Nested Conditional with Guard Clauses) | 特殊情况早返回,主干扁平 |
| 以多态取代条件 (Replace Conditional with Polymorphism) **【大】** | 按类型分支的 switch 换成多态 |
| 引入特例 (Introduce Special Case) **【大】** | 重复的"特殊值"判断换成一个特例对象 |
| 引入断言 (Introduce Assertion) | 把隐含的假设写成断言 |

### 重构 API

| 手法 | 做什么 |
|---|---|
| 将查询与修改分离 (Separate Query from Modifier) | 一个函数别既返回值又有副作用 |
| 函数参数化 (Parameterize Function) | 几个只差常量的函数合成一个带参的 |
| 移除标记参数 (Remove Flag Argument) | 布尔参数拆成多个意图明确的函数 |
| 保持对象完整 (Preserve Whole Object) | 传整个对象,别拆字段一个个传 |
| 以查询取代参数 / 以参数取代查询 (Replace Parameter with Query / vice versa) | 在"参数显式"和"内部求值"之间选 |
| 移除设值函数 (Remove Setting Method) | 不该变的字段去掉 setter |
| 以工厂函数取代构造函数 (Replace Constructor with Factory Function) | 创建逻辑需要更多灵活性时 |
| 以命令取代函数 / 以函数取代命令 (Replace Function with Command / vice versa) | 按是否需要把调用对象化来选 |

### 处理继承

| 手法 | 做什么 |
|---|---|
| 函数上移 / 字段上移 / 构造函数本体上移 (Pull Up …) | 子类共有的提到父类 |
| 函数下移 / 字段下移 (Push Down …) | 只有部分子类用的沉到子类 |
| 以子类取代类型码 (Replace Type Code with Subclasses) **【大】** | 类型码字段换成子类层次 |
| 移除子类 (Remove Subclass) | 子类没价值了,换回字段 |
| 提炼超类 (Extract Superclass) **【大】** | 两个类有共性,提一个父类 |
| 折叠继承体系 (Collapse Hierarchy) | 父子类差不多了,合并成一个 |
| 以委托取代子类 / 以委托取代超类 (Replace Subclass/Superclass with Delegate) **【大】** | 用组合代替继承,绕开继承的僵硬 |

### 大手法 = 小手法的有纪律序列

标 **【大】** 的手法会改变代码的形状,但它们**不是一步到位**的——每一个都是一串小手法的有纪律序列。例如「提炼类」:

1. 新建一个空类。
2. 搬移字段——一次一个,每次跑测试。
3. 搬移函数——一次一个,每次跑测试。
4. 收尾:检查两个类的接口,该改名的改名。

所以"大重构"和"小重构"不是两种东西,是**同一种纪律在不同跨度上的应用**:永远拆成可独立验证的小步,每步之间系统都保持可编译、可测试。跨度越大,越要守住"小步 + 每步验证"——这正是主文档铁律五。
