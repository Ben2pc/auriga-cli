# 自主目标封装

把已经澄清的工作整理成边界明确的自主目标，并按当前运行环境的真实能力启动，或输出可用的目标交接文本。goalify 只定义目标、事实来源、终点和停止条件；它是可以与计划载体组合的自主执行模式，不替代实施前的计划选择。

## 前提与事实来源

- 只在用户明确要求或选择长期自主运行时使用；普通“继续做完”“自动跑完”或“跑到待评审”先作为当前任务的延续，不据此切换目标机制。
- 计划与进度载体按工作流模板复用或选择；`goalify` 是自主执行模式，不另作计划选项。
- 需求或缺陷范围仍不清楚时，先完成 `spec-design`；技术方案需要人工确认时，先完成 `arch-design`。自主运行不能批准或绕过架构确认门禁。
- 优先引用 `docs/specs/<topic>/spec.md` 和 `validation-contract.md`，但不要求任务必须有正式规格。快速流程可以使用用户已确认的对话、问题单、当前分支、提交历史和拉取请求正文。
- 读取事实来源，不把完整规格、验证条目或拉取请求正文复制进目标。

运行中若发现新的产品语义、范围变化或实质性架构决定，向用户提出待确认项，只暂停依赖它的工作；继续有价值且已授权的独立准备，不自行选择产品或架构分支推进实现。

## 组织目标

使用以下紧凑结构，不预先编排实现步骤：

1. **目标**：说明最终要得到的可观察结果。
2. **权威事实与约束**：列出路径、问题单、拉取请求和适用的仓库工作流；基于当前任务状态推进，不假设必须重新从默认分支开始。
3. **终点与停止条件**：写明用户选择的终点、达成证据以及不能越过的边界。
4. **交接**：说明完成内容、验收方式、剩余风险和用户下一步可以做什么；依据 `validation-results.md` 或实际执行证据汇报验证结果与缺口，不能只给链接；包含评审时还要汇总发现、处理结果和保留理由。

不要在目标里硬编切片、复制现有事实正文或预判评审发现。实现阶段若触发 `incremental-impl`，由它根据当时的代码和风险决定切片。

## 确定终点

用户已经明确终点时直接采用，不重复询问。用户只选择了 goalify、但没有说明跑到哪里，或自定义终点缺少可验证的停止条件时，再询问。

- **PR Ready**：完成适用验证、正文整理和待评审标记，再完成当前工作流适用的首次评审并汇总结果，到此停止，不自动循环修复；用户明确只要求修改状态时，以该范围为终点。
- **深度评审收敛**：循环执行深度评审、修复阻塞项、验证和提交，直到最近一轮深度评审没有阻塞项、所有拉取请求检查通过，且没有未解决的阻塞性评审意见。选择该终点即表示用户明确授权为达成收敛而再次运行深度评审；协调者消费每轮报告，按授权继续修复与复验，不把单轮审查交付报告当作总任务结束；非阻塞项按最终综合的“主代理建议与判断理由”处理：`修`表示在当前拉取请求处理，`不修`表示不阻塞收敛并在交接中保留理由。
- **合并**：只有用户明确授权合并时才能采用；完成评审、检查和合并后停止。
- **自定义终点**：采用用户给出的可验证停止条件。

终点为 PR Ready 或更后阶段时，用户已经明确选择资料去向就沿用；否则默认把本次拉取请求的临时规格和规划资料归档到 `docs/worklog/worklog-<YYYY-MM-DD>-<branch-name>/`（归档用 `documentation-management` 执行，不直接移动文件），同步相关长期规范的状态和引用，然后继续向既定终点推进，不为资料处置停下询问。

## 启动与交接

- 先检查当前实际可调用的目标启动工具及参数约束，复用属于当前任务的已有目标或载体，不按宿主名称猜测能力。按用户授权设置目标；只有工具确认成功后才称“已启动”，结果不确定时先查状态，不重复创建。
- 没有启动能力时输出包含上述目标结构的交接文本，并明确“仅生成指令，尚未启动”；只有目标运行时实际支持 `/goal` 时才提供该命令形式，不虚构后台运行。
- 到达终点后立即交接，不自行进入未授权阶段。触发待确认条件时说明被暂停的工作与仍可推进的独立事项；无可继续工作时交回用户。
