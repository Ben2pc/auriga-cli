# `arch_design.md` 模板

存在实质性的架构、领域模型或跨边界决策时，将下面的模板复制到 `docs/specs/<topic>/arch_design.md`，并在实现开始前交给用户评审。

使用约定：

- 保留双语章节标题，正文使用对话语言。
- 删除写作提示、占位符和不适用的可选章节。
- 先写评审重点，再展示当前架构现状和当前目录结构，之后才写支撑细节。
- 当前与目标整体架构图保持同一抽象层级、相近布局和一致命名，让评审者直接看出改变前后；整体图优先采用 C4 模型的容器或组件语义，可用 Mermaid `flowchart` 表达以保证渲染兼容性。
- 新方案改变模块、组件或目录布局时，保留目标整体架构图和目标目录结构；没有改变的部分不重复展开。
- 细节图按评审问题选择：跨组件调用用 `sequenceDiagram`，生命周期与状态转换用 `stateDiagram-v2`，持久化数据关系用 `erDiagram`，重要领域类型关系用 `classDiagram`，数据流、部署拓扑和迁移路径用 `flowchart`。不为完整形式机械补图。
- 用户确认后更新评审状态；未确认前不进入实现。
- `Alternatives & Tradeoffs` 仅在存在真实取舍时保留本节，不为完整形式制造候选。

````markdown
- **核心决定**：<需要确认的结构或领域决定>

> 保留本节并展示设计前的整体结构。已有系统画当前模块、组件、外部依赖和关键依赖方向；全新系统明确写“当前无实现”，并画出将要接入的现有系统边界。整体图使用 C4 模型的容器或组件语义，并与后文目标图保持同一抽象层级。

flowchart LR

```
````
