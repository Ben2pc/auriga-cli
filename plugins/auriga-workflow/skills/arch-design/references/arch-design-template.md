# `arch_design.md` 模板

按技能的写作原则写；下面的骨架是章节、模型、接口、图和附录的唯一详细契约。未标“按需”的是必填；标“按需”的没有内容就整节或整行删除，不写“无”。

使用约定：

- 标题只用中文，最多四级；交叉引用写带名字的链接，例如“见[上游响应处理](#上游响应处理)”，不写裸章节号。
- 已有代码实体沿用仓库标识符，新增实体用本设计定义的标识符；正文、表格、图和示例保持一致，不翻译实体名。
- **写入判据**：只写跨模块、跨服务或对外的契约，以及改变它需要评审者重新拍板的选择。不写实施者读代码就能得出的细节，例如被排除项的逐个列举、模块内部参数、完整函数签名；也不写分支名、实施单元、提交拆分和操作流水，它们属于计划、验证结果和工作记录。
- **契约完整展示一次**：接口请求与响应、消息载荷、登记格式在主要承接它的分项完整展示一次，不受篇幅压缩；再次出现时引用首次展示的位置。
- **表与图**：三个以上的条件分支写成表；三个以上、彼此有转换的状态画状态图，并配“状态、行为、能否退回”表；模块或依赖关系改变时画前后对比图，两张图同一抽象层级。图先写业务含义，代码标识放括号里，不写完整调用签名或查询语句。
- 评审者不熟悉的技术名词第一次出现时，用一句话说明它做什么。
- 修订直接改正文；确认后在附录的确认记录加一行，不追加“取代前文”或回写段落。
- **长期规格拆成子规范时**：本文件是总设计，只放决策页、设计边界、模块落点、被两个以上子设计使用的共享模型、子设计索引（含进度）、上线阶段和跨子设计的风险；每个子规范目录放一份子设计，按“分项设计”写。

#### `<模型名>`（<类型>，新增 | 修改 | 删除 | 不变）（按需）

每个模型一个标题，先写一行“代码位置”（已有实体写仓库路径，新增写预计路径），再只写它的类型用得到的字段：

| 领域实体 | 职责、唯一标识、生命周期 | 规则（检查时机）；状态三个以上时画状态图 |
| 值对象 | 字段与取值约束、相等规则 | 规则（检查时机） |
| 枚举或状态 | 取值表：值、含义、何时进入 | 转换图 |
| 数据库表 | 主键与唯一约束、字段改动表 | 索引、外键、迁移方式 |

#### 接口（按需）

进程内接口，只写承载模块边界、依赖方向或可替换实现的：

`<Type.method(a: A, b: B) -> C>`
输入 a、b，返回 C。失败（按需）：<D，什么时候>。

HTTP 接口，标题写“方法 路径（新增 | 修改）”：

`POST /api/v1/<path>`（新增）：<谁调用，做什么>。鉴权：<身份与权限>。重复请求（写操作）：<幂等键或语义>。

```jsonc
// 请求 CreateResourceRequest（新增）
{ "resource_id": "res-1", "items": [{ "item_id": "item-1", "value": "v" }] } // item_id：资源内唯一
```

```jsonc
// 成功响应 ResourceResult（复用）
{ "resource_id": "res-1", "status": "accepted", "updated_at": "2026-08-20T10:00:00Z" }
```

| 情况 | HTTP 状态 | 错误码 | 调用方看到什么 |
|---|---|---|---|
