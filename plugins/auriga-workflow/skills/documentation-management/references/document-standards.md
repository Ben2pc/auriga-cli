# 工程文档基本规范

只读取并应用本次任务涉及的类型。项目已有规范优先。

## README 与开发指南

- 说明项目用途、目标读者和适用范围。
- 以 overview 与图（如 mermaid）为主建立心智模型；细节交给代码与 Agent 文档。
- 提供已验证的前置条件、最短可运行路径和常用命令。
- 解释关键目录或开发入口，并导航到唯一的详细信息源。
- 只在真实需要时加入配置、故障处理、贡献或架构章节。

## 运行手册

- 写清触发场景、前置权限与依赖、操作步骤和预期信号。
- 包含验证、失败处理、回滚或停止条件，以及必要的升级路径和负责人。
- 区分日常操作与事故处置；危险命令标明影响范围和确认点。

## 公共接口文档

- 优先维护最接近实现的信息源：类型、schema、OpenAPI 或代码生成输入。
- 说明调用方需要知道的输入、输出、错误、鉴权、兼容性和副作用。
- 只为不明显的用法提供示例，不逐字复述签名或生成内容。
- 接口废弃或迁移时写明替代方案、兼容窗口和删除条件。

## 架构文档

- 描述当前结构、职责边界、依赖方向、关键接口、数据流和技术质量约束。
- 图与目录必须对应当前代码，并突出读者需要判断的关系。
- 当前架构文档维护“现在是什么”；历史选择及其理由交给 ADR，本次实施、评审、修订和上线经过留在 worklog、拉取请求或问题记录。

## 架构决策记录

- 价值排序是为什么 > 是什么：背景、约束和真实备选与取舍承载长期价值，结论只需一句话；不把初稿变化、评审轮次、修订提交或上线经过写成决策理由。
- ADR 可以同时服务人类与 Agent。若它包含某个作用域内 Agent 必须理解的当前决定，由该作用域的 `AGENTS.md` 建立索引并说明读取条件；不要把所有 ADR 无差别挂到仓库根。

最小结构：

```markdown
# ADR-NNN：<决定>

## 状态
提议 | 已接受 | 被 ADR-XXX 取代 | 已废弃

## 日期
YYYY-MM-DD

## 背景与约束
<为什么现在必须决定；哪些事实和约束影响选择>

## 决定
<已确认的选择及适用范围>

## 真实备选与取舍
<只记录实际考虑过且能成立的方案；没有真实备选时删除本节>

## 后果
<得到什么、承担什么、需要持续遵守或跟进什么>
```

## 内联注释

- 解释不明显的原因、不变量、顺序要求、副作用、兼容限制或已知陷阱。
- 不复述代码，不保留注释掉的旧实现，不用注释掩盖应立即修复的问题。
- 约束跨越多个调用点时，提升到共享规则或架构文档，并在代码附近保留短导航。

## 变更日志与发布说明

- 仅在项目已经采用该资产或发布流程明确要求时维护，不默认新建。
- 记录用户或调用方能观察到的新增、变更、修复、废弃和迁移动作。
- 使用实际版本与发布日期；不要复制提交列表或内部重构细节。

## Agent 文档

- 先区分供 Agent 查询的工程资料与直接控制 Agent 行为的指令。架构文档、接口契约、schema、ADR 等资料沿用各自的内容规范，不套用提示词结构。
- 分层维护 `AGENTS.md`。仓库根文件只说明全局目标、约束、目录路由和验证入口；具有独立职责、命令或约束的子包在自己的根目录维护作用域文件。
- 子级 `AGENTS.md` 只增加或收窄本作用域规则，不复制祖先内容；每层保持 `CLAUDE.md -> AGENTS.md` 兼容软链。
- 子作用域 `AGENTS.md` 必须由父级单行指针指向；其余文档索引是可选优化，只收录有明确读取条件的承重文档。跨多个子包的共同文档提升到最近公共祖先，不把全部索引集中到仓库根。
- 优先承载代码推不出来的事实与决策理由；不复述代码细节，代码级补充下沉为行内注释。
- 按实际消费者和内容选择规范，不由文件名决定；同一事实被人类与 Agent 使用时保持唯一来源。
- 每条指令只写一次，并以当前时态表达稳定规则；删除同义重复、模型已稳定具备的过程教学、不改变行为的示例，以及本次实施或评审经过。
- 仅对提示词、项目规则和标准操作流程等行为指令，按需用目标、成功标准、权限边界、证据要求、工具路由、输出契约和停止条件组织。
- 保持稳定前缀，减少无意义改写；压缩后仍必须保留相同功能契约。
- 资料引用按 `documentation-management` 的消费者与读取条件规则判断；人类指南中的唯一权威步骤可以直接引用，不为分离读者复制文档。
