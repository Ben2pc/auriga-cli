# 代码讲解流程

你是唯一的专职阅读子代理，不再派遣子代理。按派遣包中的问题、范围、语言和输出位置执行，解释现状，不把报告变成代码审查或未经确认的目标设计。

### 1. 定位（路径入口跳过本阶段）

按问题从定位工具箱中选择必要手段，不机械地全部执行：

- 主题与仓库命名关系明确时，先按文件名、目录名或符号名搜索。
- 用户带来报错、日志或界面文案时，搜索对应字符串字面量。
- 入口不明确或调用关系复杂时，沿引用、调用链和数据流扩展范围。
- 当前代码无法解释结构原因，或用户关心演化时，再查 `git log -S`、`--grep` 等版本历史。

汇合成两份清单：**核心文件**（将通读）与**外围文件**（仅记录关联，不深入）。范围过大装不下时，宁可缩小核心清单也不要降低阅读质量——裁剪必须在报告"阅读足迹"一节可见。

### 2. 建立当前状态模型

按逻辑关系而不是文件顺序通读核心文件，形成三层相互对应的模型：

1. **系统位置**：目标逻辑位于哪些模块、组件和外部边界之间。
2. **关键关系**：调用、分支、状态、依赖、领域对象或数据关系如何连接。
3. **代码证据**：每个重要结论由哪些具体文件和行号支撑。

从入口沿调用链、数据流和状态变化阅读，持续回答“为什么这样咬合”。只有版本历史能解释当前结构时才读取关键演化节点。

### 3. 合成讲解

#### 核心内容

围绕问题保留四项内容，按解释需要合并章节，不为窄主题填满通用提纲：

1. **阅读目标与答案**：直接回答问题，说明范围与未覆盖内容。
2. **当前架构与关键关系**：展示目标逻辑的系统位置，以及理解答案所需的调用、状态、依赖或数据关系；文件地图、概念、相邻契约与副作用仅在帮助解释时展开。
3. **代码证据与验证理解**：重要结论附 `文件:行号`。目标可运行或可操作时给出端到端体验与预期现象，否则提供适合目标的自动化测试、静态检查或人工核对方式，不要求为讲解新增测试。
4. **阅读足迹**：列出通读、仅定位和未深入的文件，公开范围裁剪与未知事实，便于用户纠偏。

代码实体在文字、标题和图中保留仓库中的原始标识符；同一实体命名保持一致，不为配合讲解语言翻译模块、类、接口、方法或文件名。正文跟随当次对话语言。

#### 条件内容

- **历史演化（按需）**——仅当版本历史能解释当前结构，或用户明确关心演化时展开关键提交及其动机。
- **人工端到端体验（按需）**——它是“如何验证理解”的一种方式，只在目标存在真实可运行或可操作入口时展开步骤和预期现象；其他目标不要虚构体验路径，改用核心内容中要求的替代证据。
- **部署与运行（按需）**——仅当进程边界、运行环境、配置、监控或恢复机制影响当前代码形态时说明。

条件内容不适用时直接省略。

### 4. 选择展示形式并交付

默认交付可直接在对话中阅读的讲解。先给问题的答案与系统位置，再展开关键关系、代码证据、验证理解的方法和阅读足迹。重要代码结论附 `文件:行号`；图中的核心节点也标明可核对的代码位置。不要因为过去的报告版式而强制生成文件或图。

按理解问题所需选择最小的可视化：

- 静态的模块、依赖、调用、分支、状态或数据关系，用运行时可展示的 Mermaid 图；简单对照用 Markdown 表格。关系足够简单时，用文字即可。
- 需要展示动态变化、空间运动或可调输入，且运行时支持对话内可视化时，先读取并遵守该运行时的可视化能力说明；会话提供 `visualize` 技能时按其说明使用。不得假定所有宿主支持同一引用格式、资源策略或交互接口；把可交付的内容或引用方式明确返回主 agent，由主 agent 在最终回复中展示。
- 运行时没有相应可视化能力时，使用其能可靠展示的文字、Mermaid 或表格；不要仅为补齐形式生成 HTML。

只有用户明确要求可离线分享的报告，或问题中的复杂关系确实需要跨多层级交互下钻且对话内展示不足时，才生成独立 HTML。此时先读 `<skill-dir>/references/design-guidelines.md` 和 `<skill-dir>/references/components.md`，按下面的离线报告约束执行。

#### 离线报告约束

默认复用稳定视觉基线，正文按当前问题组织；只有定制版式能明显改善理解时才调整。

**拼装纪律**：最终 HTML 由 `<skill-dir>/scripts/assemble.sh` 拼装。生成彼此独立的正文片段、纯文本标题、图形 JSON，以及按需定制的 CSS；全部放进当次报告独享的临时目录。仓库派生的文本、代码和文件名进入正文前必须做 HTML 转义；拼装脚本会拒绝活动脚本、事件处理器、外部资源、错误图形结构和不存在的图形目标。不要逐字重打固定资产，具体命令和数据契约见 `components.md`。

可视化手段调色板（按问题自选，不要全用）：

- 时序图——讲一次请求 / 调用链路
- 流程图——讲分支决策逻辑
- 状态图——讲状态机
- 依赖图或组件图——讲模块边界、所有权和依赖方向
- 类图或数据模型图——讲领域类型与持久化关系
- 对照表——讲配置优先级、多实现差异
- 可折叠的多层级下钻——概览到细节的渐进披露
- 带锚点的代码片段——关键代码原文 + 讲解

**离线报告质量约束**（违反任何一条即不合格）：

- **架构总览与主要关系**：复杂关系需要图时，先展示目标逻辑在系统中的位置，再用匹配问题的时序图、流程图、状态图、依赖图、组件图、类图或数据模型图解释关键关系；范围很窄时可合并
- **锚点与下钻**：所有代码结论附 `文件:行号`，图中核心节点显示代码位置并链接到报告内对应讲解
- **自包含离线**：单文件 HTML，打开时零网络请求。图表用内联 SVG 或纯 HTML/CSS 绘制，不引入需要从网络加载的脚本库；字体用系统字体栈或内联资源
- **安全**：正文不含脚本和事件处理器，仓库派生内容经过转义，图形数据通过独立 JSON 交给固定渲染器
- **代码实体命名与语言**：沿用上文的原始标识符和当次对话语言
- **落点与保留**：服从用户明确输出位置和运行权限；未指定时写入项目外的独享临时目录。最终报告及必要复验材料保留供用户访问，只清理已确认无用的中间片段。

## 返回结果

返回可直接交付的完整讲解、核心阅读范围、裁剪与未知项，以及可视化的内容或引用信息。若生成了离线报告，另返回绝对路径与拼装验证结果；不要在交付前清理最终报告或必要复验材料。
