# 理解报告的前端设计规范

摘取改编自 frontend-design 的审美准则，针对 docent 的场景收窄：这是一份**供人阅读的代码理解制品**，可读性和信息密度优先，审美为理解服务。生成报告 HTML 前通读本文件。

## 默认视觉基线

默认使用组件库提供的 design token、排版层级、图表容器和交互样式，形成稳定、可读的报告基线。正文结构和图的选型跟随当前问题；只有主题、阅读环境或信息结构确实需要时，才整体调整色板或版式。

不要为了显示设计感而堆叠渐变、卡片、动效或装饰。定制必须能回答一个具体的理解问题，例如突出关键路径、区分状态层级或让宽图更容易浏览。

## 排版

- 默认采用固定资产中的系统字体栈、标题层级和正文行距。只有主题或阅读环境需要不同的信息密度时才覆盖这些值，并说明它怎样改善理解。
- 代码一律等宽字体，行高放宽到 1.5 以上；代码块要带 `文件:行号` 锚点标签。
- 中文正文行高 ≥1.7，段宽控制在 65–75 字符，长文不顶满屏宽。

## 色彩与主题

- **默认从 components.md 的 design token 基准色板出发**（暖纸面底 + 炭墨 + 珊瑚主色 + 青 / 琥珀强调，与 session-compound 同源）。需要暗色或其他主题时可以整体替换 token 取值，但变量名保持不变，组件自动跟随。
- 一个主导色 + 少量锐利强调色，胜过平均分布的胆怯配色；语法高亮、图表、强调色都从同一色板派生。
- 强调色留给真正重要的东西：主色 `--primary`（珊瑚）给锚点与流程图关键路径，`--warning` / `--error` 给警示性的坑，`--accent-teal` 给正向结论。

## 信息架构与空间

- 报告按“系统位置 → 关键关系 → 代码证据”三级下钻。先给一屏内能读完的一句话答案和当前架构总览，再展示文件级地图与主要关系图，最后沿图中节点进入文件和行号证据。
- 不按文件读取顺序组织正文。相同模块、状态和角色在架构图、关系图、目录树和章节中使用一致命名与颜色。
- 图中核心、外围、外部和未知内容要有稳定的视觉区分；未知事实不能用推测补齐。
- 内容较长时使用目录或粘性侧栏导航，让核心内容可以直接跳转。
- 布局可以打破常规（不对称、跨栏的图、留白制造节奏），但永远不牺牲阅读顺序的清晰。

## 图表

- **按理解问题选图**：跨组件调用用时序图，分支处理用流程图，生命周期用状态图，模块所有权与依赖方向用依赖图或组件图，领域类型用类图，持久化关系用数据模型图，配置覆盖用优先级表或决策表。不要把静态关系硬画成流程。
- **实现优先级**：① 组件库渲染器；② 表达力不够时用已安装的本机图形工具渲染静态 SVG；③ 工具不可用且手绘确实能改善理解时，才使用小范围内联 SVG，并在交付前做视觉检查。三种方式都不得引入打开报告时需要联网的资源。
- **目录树严禁用 ASCII 字符画**（`│ ├ └` 这类字符贴进 HTML 后会因字体度量与换行错位）。直接用 components.md 的 `file-tree` 组件：嵌套列表 + CSS 缩进引导线，目录节点可折叠，文件节点旁标注角色一句话。
- 图中节点用 `anchor` 标注 `文件:行号`，用 `href` 链接到对应讲解段落；详细章节按需提供返回总览的链接。
- 图例、配色与全局色板一致；关键路径用强调色，外围路径降饱和。

## 动效与交互

- 优先纯 CSS 实现：折叠展开的过渡、锚点高亮、悬停显示锚点详情。
- 动效服务理解：一次编排好的入场渐显（用 animation-delay 错峰）胜过到处乱动的微交互。
- 交互三件套优先做好：可折叠章节、目录跳转、代码块一键复制。

## 内容安全

- 正文片段只包含结构化 HTML 和经过转义的仓库文本，不包含 `<script>`、事件处理属性或外部资源。
- 图形数据放进独立 JSON，由固定引导脚本渲染；不要把仓库中的字符串拼进可执行 JavaScript。
- 代码片段中的 HTML、脚本和事件属性必须作为文本转义展示。拼装脚本拒绝活动内容时，修正文输入，不绕过检查。

## 完成度检查

交付前自查：零网络请求（断网打开完整渲染）；单文件；所有图表渲染正常；折叠/跳转交互可用；固定视觉基线已正确注入；若使用定制 CSS，能指出它解决的具体理解问题。
