# 理解报告的前端设计规范

摘取改编自 frontend-design 的审美准则，针对 docent 的场景收窄：这是一份**供人阅读的代码理解制品**，可读性和信息密度优先，审美为理解服务。生成报告 HTML 前通读本文件。

## 设计立场

动笔前先选定一个明确的美学方向并贯彻到底：编辑部杂志风、克制的极简、工程蓝图风、暗色终端风、纸面笔记风……方向本身不限，关键是**有意图**——每一份报告都该像被认真设计过，而不是默认样式的堆叠。两份不同主题的报告不应该长得一样。

**绝对避免同质化的"AI 默认审美"**：

- 不用烂大街的字体（Inter、Roboto、Arial、裸 system-ui 不加调味）
- 不用紫色渐变配白底这类陈词滥调配色
- 不用千篇一律的卡片网格布局
- 不要每代生成都收敛到同一种选择

## 排版

- 标题用有性格的展示字体，正文用高可读性字体，两者搭配出层次。受"零网络请求"约束，从系统字体栈里做有意图的挑选与组合（例如衬线标题 + 无衬线正文、或等宽点缀），用字重、字号、字距制造对比。
- 代码一律等宽字体，行高放宽到 1.5 以上；代码块要带 `文件:行号` 锚点标签。
- 中文正文行高 ≥1.7，段宽控制在 65–75 字符，长文不顶满屏宽。

## 色彩与主题

- 用 CSS 变量统一色板；一个主导色 + 少量锐利强调色，胜过平均分布的胆怯配色。
- 暗色或亮色主题都可以，但要一以贯之；语法高亮、图表、强调色都从同一色板派生。
- 强调色留给真正重要的东西：锚点、警示性的坑、流程图中的关键路径。

## 信息架构与空间

- 报告是**渐进披露**的：先给一屏内能读完的概览（这段逻辑是什么、一张主图），细节放进可折叠区域或锚点跳转的章节。
- 善用目录 / 粘性侧栏导航，十条必答各有可跳转锚点。
- 布局可以打破常规（不对称、跨栏的图、留白制造节奏），但永远不牺牲阅读顺序的清晰。

## 图表

- 图表用**内联 SVG 或纯 HTML/CSS** 绘制（流程框线、时序泳道、状态圆角框都能用 flexbox/grid + 边框 + 伪元素画出来），不引入需要网络加载的脚本库。
- 图中节点标注 `文件:行号`，可点击跳到对应讲解段落。
- 图例、配色与全局色板一致；关键路径用强调色，外围路径降饱和。

## 动效与交互

- 优先纯 CSS 实现：折叠展开的过渡、锚点高亮、悬停显示锚点详情。
- 动效服务理解：一次编排好的入场渐显（用 animation-delay 错峰）胜过到处乱动的微交互。
- 交互三件套优先做好：可折叠章节、目录跳转、代码块一键复制。

## 完成度检查

交付前自查：零网络请求（断网打开完整渲染）；单文件；所有图表渲染正常；折叠/跳转交互可用；配色与字体体现了明确的设计立场而非默认值。
