# `validation-contract.md` 模板

文件化规格没有拆成子规范时，与 `spec.md` 配套写入同一目录；拆分后只在每个子规范目录中与对应 `spec.md` 配套，总规格的父级验收锚点直接写在总 `spec.md`。一条 VAL 是一项验收断言，不代表一个测试用例；实现阶段可以按风险展开为多个必要用例。

使用约定：

- 本文件只定义通过标准；配套的 `validation-results.md` 保存当前覆盖和实际交付验证事实，也可记录契约外的额外验证。结果格式与生命周期见 `spec-design`，不把执行记录填回本契约。
- 使用与 `spec.md` 相同的产品分组、叶子功能名称和顺序；覆盖总览负责快速索引，断言正文按叶子功能归组。多层结构中的非叶子章节只作为分组标题，不直接承载 VAL；新增、合并或重命名规格分项时同步更新本文件。
- 每个适用产品分项都要在覆盖总览中写明主要验证证据，证据可以来自单层或多层。当用户结果依赖真实产品表面或跨层协作时，再补充少量代表性产品验收路径；其中 Agent 可执行的端到端验收路径只用于证明这类结果，一条路径可以覆盖多个相邻分项，不要求每条 VAL 分别做端到端验收，也不替代更直接的分层证据。
- 验证方式按断言风险选择，可以是仓库检查、静态分析、单元测试、组件测试、契约测试、集成测试、HTTP 测试、界面自动化、运行探测或端到端验收；这些是开放示例，不是封闭清单，优先选择能直接证明断言且维护成本合理的证据。
- 客户端工程：当正确性依赖真实界面、系统权限或运行时集成时，至少保留一条代表性真实界面验收，可以使用 UI 自动化，或由 Agent 通过 MCP/CLI 驱动模拟器或真机；其余断言可以使用更直接的组件、状态、可访问性或集成证据。
- 前端工程：当正确性依赖真实界面或浏览器集成时，至少保留一条代表性真实界面验收，可以使用 UI 自动化，或由 Agent 通过 MCP/CLI 驱动真实浏览器；其余断言可以使用更直接的组件、状态、可访问性或集成证据。
- 服务端 API：新增或改变的接口行为至少有一条 Agent 可执行的 HTTP 测试或接口端到端验收；可以由脚本直接调用，也可以由真实客户端或前端页面触发接口验收；协议形状、业务规则和内部协作仍可分别使用契约、单元或集成证据。
- 关键状态、危险操作、错误恢复和用户可见文案应按真实风险形成验收断言；不要求每句文案各占一条 VAL，同一状态或流程中不可分割的文案契约可以一起验证。
- 服务端下发的文案可以通过接口契约或 HTTP 测试证明触发条件、最终文本、动态变量和兜底；只有最终正确性依赖真实客户端展示时，才补充代表性界面验收。
- 优先使用 Agent 验收。人工验收只作为例外；必须在 Agent 验收路径中写明无法可靠自动观察的原因、需要人判断的内容和操作入口，不能只写“人工确认”。
- 编号使用 `VAL-<完整语义分类>-<NNN>`；分类使用完整、稳定的英文单词，不限制长度，不使用项目自造缩写。同一行为领域复用分类并连续编号。
- 编号后增加简短的中文标题；编号用于稳定引用，标题用于表达含义。
- `验收要求` 只表达一个可观察结果，不能让两种明显不同的行为都算通过。
- `验证方式` 写最直接且与风险匹配的证据类别，不把覆盖总览中的代表性产品验收路径复制到每条 VAL。只有断言本身依赖真实产品表面时才引用该路径；其他断言可以使用单元、组件、契约、集成、静态检查、运行探测或更贴合项目的证据，不维护封闭词表。
- `通过标准` 写什么结果算通过，不写测试函数、测试夹具、模拟方式、驱动或实现步骤。
- 具体测试工具由 `test-driven-development` 根据项目测试规则和现有设施决定，不在本文件复制工具链清单。

```markdown
# Validation Contract — <主题>（验收契约 — <主题>）

> 与 spec.md 配套：spec.md 描述 why + 用户可观察的 what；本文件描述什么算通过。
> 一条 VAL 不等于一个验证用例。

## 1. Coverage Overview / 覆盖总览

|---|---|---|---|

## 2. Assertions by Product Requirement / 按产品分项组织断言

> 以下是单层叶子功能示例。`spec.md` 存在多层产品结构时，先复制相同的非叶子分组标题，再在叶子功能标题下展开 VAL；VAL 标题始终比叶子功能标题低一级。

### 2.1 `<与 spec.md 一致的产品分项名称>`

#### VAL-ALIGNMENT-001 — <简短的中文标题>
- **验收要求**：<单一含义的用户或调用方可观察结果>
- **验证方式**：<适合证明它的证据类别；涉及真实产品表面时引用覆盖总览中的 Agent 验收路径>
- **通过标准**：<出现什么结果才算通过>
```
