# `spec.md` 模板

文件化规格触发时，将下面的模板复制到 `docs/specs/<topic>/spec.md`。跨多个 PR 的总规范只有在用户明确确认长期生命周期后，才写入 `docs/long-running-specs/<topic>/spec.md`。需求未拆分时，本文件与 `validation-contract.md` 配套；需求拆成多个子规范时，本文件作为总规格与 `umbrella.md` 配套，子规范分别放在同一总规范目录的子目录中。

使用约定：

- 保留双语章节标题和层级编号，正文使用对话语言；删除写作提示和占位符，不适用的可选章节直接删除，不用“无”填满形式。
- 按“产品总览 → 产品需求分项”组织。总览只保存共同目标、整体体验、共享产品规则和范围；每个分项保存一组紧密相关的原始需求及其用户可感知行为。
- 优先根据原始产品需求描述或 PRD 的产品功能结构组织分项：沿用有业务意义的章节名称、层级和顺序，并在来源结构对齐表中记录对应关系；背景、修订记录、排期等非功能章节不机械复制为需求分项。多层结构中，非叶子章节只作为产品分组标题，叶子功能使用下一层编号，并在叶子下用“原始产品需求、用户可感知行为、交互设计、范围边界、验收映射”五个粗体字段展开；只有一层功能结构时使用模板中的 `2.1` 单层叶子写法。不要让固定内容标题占用或压平产品自身层级。
- 没有可参考的前置产物或来源结构时，按用户可感知的产品子功能划分。一个子功能应有用户能够识别的触发场景和可观察结果；不能按后端模块、接口、数据表、类或实施步骤划分产品需求。
- 跨多个分项共同成立的产品规则只在总览定义一次，分项引用；原始需求必须落入具体分项，不能只留在总览概括。
- 涉及用户交互的叶子功能保留“交互设计”，并按真实用户任务写到可实施程度。生产级用户表面必须写出本次新增或改变的具体文案；服务端下发或配置的文案同样属于产品契约。确实不涉及用户交互的分项删除该段，不用占位内容填充。
- `validation-contract.md` 使用与本文件相同的产品分组、叶子功能名称和顺序；只在叶子功能下列出对应 VAL，避免另建一套验收分类结构。
- 独立规格与子规范初始化 `validation-results.md`；总规格仅在实际开展跨规范验收时创建。格式与生命周期见 `spec-design`，本文件不复制结果。
- 本文件作为拆分后的总规格时，不另建总体验收契约；各叶子功能的“验收映射”保存父级验收锚点，`umbrella.md` 再把这些锚点映射到各子规范自己的 `validation-contract.md`。
- 可先保存待确认草稿，标明未决产品决定；确认后更新状态并记录确认来源，只保留最终决定，不保存逐题问答流水。
- 草稿的 `Open questions` 可列出待确认的产品问题；已确认版本只保留有意交给架构或实施阶段的决定，并写明归属和推迟理由。未决产品问题不能作为实施依据。

|---|---|---|---|

## 2. Product Requirement Details / 产品需求分项

> 有产品需求文档时，按其中有业务意义的产品功能章节命名和排序；没有来源结构时，按用户可感知的产品子功能组织。以下 `2.1` 是只有一层功能结构时的叶子示例，可以复制为其他同级分项。来源存在多层产品结构时，先按原层级建立只负责分组的非叶子标题，再在每个叶子功能下用“**原始产品需求**、**用户可感知行为**、适用的 **交互设计**、**范围边界**、**验收映射**”五个字段展开同样内容，不套用下面固定的 `2.1.1`～`2.1.5` 内容编号。

### 2.1 `<产品需求文档中的功能章节，或用户可感知的产品子功能>`

#### 2.1.1 Original Product Requirement / 原始产品需求

- **来源**：`<来源文件或用户已确认描述>#<章节、条款或定位信息>`
- **原始需求**：<忠实概括该分项承接的原始产品要求；保留会改变用户结果的条件，不改写成技术方案。>

#### 2.1.2 User-visible Behavior / 用户可感知行为

- **目标用户与场景**：<谁在什么场景进入本子功能。>
- **触发与前置条件**：<用户做什么，或什么产品事件发生。>
- **主要行为**：<按用户视角描述交互、状态变化或调用结果。>
- **成功结果**：<用户或调用方最终观察到什么。>
- **失败与边界行为**：<无权限、空状态、重复操作、部分失败或其他真实边界下会观察到什么。>
- **兼容要求**：<既有用户、调用方或数据必须保持的行为；不适用时删除。>

#### 2.1.3 Interaction Design / 交互设计

> 涉及用户交互时保留。结合真实产品表面和用户任务，使用尼尔森十大可用性启发式发现相关风险，但不机械生成逐项清单。生产级用户表面写出本次新增或改变的全部用户可见文案；未改变的既有文案不重复抄录。

**交互与动效**

| 场景与目标 | 入口与前置条件 | 操作、控制与效率 | 状态反馈与恢复 | 动效与过渡 | 无障碍与适配 |
|---|---|---|---|---|---|
| `<用户在什么场景要完成什么；设计要降低什么理解、记忆或操作成本>` | `<入口、触发条件及必要前置状态>` | `<主要操作、返回、取消、撤销、高频路径，以及沿用的平台惯例、设计系统或已有组件>` | `<加载、空状态、处理中、成功、失败及恢复方式>` | `<状态变化、进入退出、手势或其他必要动效；包含持续时间、可中断性及减少动态效果要求>` | `<焦点、语义、键盘、动态字体、尺寸或本地化适配要求>` |
