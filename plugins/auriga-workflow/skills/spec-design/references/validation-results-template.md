# `validation-results.md` 模板

与当前任务的验收契约配套，保存可复核的交付验证事实，供执行者、评审者和用户消费；不是新的需求来源，也不是调试日志。创建、拆分和归档位置见 `spec-design`。

## 记录规则

- **按验证活动记录。** 每完成一个有明确验收目的、用于判断实施单元或整体交付的验证活动，就及时追加一条；一次测试集运行或一条完整界面验收路径可以是一条，不按测试用例或命令调用拆分。额外的兼容性、性能、构建、静态检查、接口探测、人工或视觉验证同样可以记录，不限定证据类别。
- **不记录开发试跑。** 常规预期失败、局部试跑、调试探针以及已修正且不影响交付判断的临时失误不逐次入档。选作交付验证的活动即使失败或阻塞也必须记录；不能因尚未通过就当作调试过程省略。
- **关联而不复制契约。** 一条结果可关联多条验收要求，一条要求也可引用多份结果；未对应契约的活动标为“额外验证：<目的>”，不编造验收编号。结果不反向放宽通过标准；新增需求决定返回 `spec-design` 确认。
- **记录对象和观察。** 写清执行时间、代码版本或可识别的工作树状态、必要环境，以及实际命令或操作、观察结果和局限。提交号不能掩盖未提交修改；命令成功不自动等于需求通过。引用他人或持续集成证据时注明来源，不写成自己执行；证据不可访问时说明缺口。保留关键摘要和可访问的日志、截图或运行链接，不复制完整输出、秘密或个人数据。
- **区分历史与当前。** 已登记活动的失败、阻塞和通过事实保留，复验追加新记录并引用旧记录。后续相关修改使证据不再适用时，把受影响验收标为“待复验”；仅收集新的相关证据，不因无关改动重跑全部验证。
- **覆盖必须诚实。** 初始化时按契约顺序列全当前任务的验收要求，标为“未执行”，验证记录写“尚未执行验证”。新确认的要求同步纳入覆盖表。需要多份证据的要求只有全部证据有效且满足通过标准才算通过；未执行、失败、阻塞、待复验均不算通过。“不适用”须引用已确认的范围决定，不能由执行者自行豁免。没有验收编号时使用可定位的用户要求；不为填表另造契约。
- **交接面向用户。** 收尾根据当前覆盖和额外验证，直接报告完成了哪些验证、结果如何、未完成或受限项目及影响，并链接完整记录；不能只给文件链接或用测试总数替代验收结论。快速流程没有文件时，在对话中给出同等摘要，不补建整套规格。

以下代码块是生成的 `validation-results.md` 正文模板。初始化时保留覆盖表，删除示例记录；实际记录时删除占位提示。覆盖表按契约的产品分项顺序排列，记录正文按执行顺序排列，不复制整套产品章节。
