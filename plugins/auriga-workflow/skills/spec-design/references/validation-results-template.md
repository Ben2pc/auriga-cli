# `validation-results.md` 模板

保存可复核的交付验证事实，供执行者、评审者和用户使用；不替代需求，也不记调试日志。位置与生命周期见 `spec-design`。

## 记录规则

- **粒度。** 每完成一个支撑单元或整体交付判断的验证活动就追加一条，如一次测试集运行或完整界面验收；不按用例或命令拆分。契约外的验证也可记录，不限证据类别。
- **取舍。** 不逐次记录预期失败、局部试跑、调试探针及无交付影响的临时失误；交付验证即使失败或阻塞也要记录。
- **关联。** 结果与要求可多对多关联；契约外活动标为“额外验证：<目的>”，不编造编号。不得放宽通过标准；新需求返回 `spec-design` 确认。
- **证据。** 写清时间、版本及未提交改动、环境、执行、观察和局限；命令成功不等于验收通过。引用他人或持续集成结果须注明来源，不可访问时列出缺口。只保留可复核摘要和证据定位，不复制完整输出、秘密或个人数据。
- **复验。** 保留已登记事实，复验追加并引用旧记录。相关改动使证据失效时标为“待复验”，仅补相关证据，不因无关改动全部重跑。
- **覆盖。** 按契约顺序列全当前要求，初始化为“未执行”，新确认要求同步纳入。全部必要证据有效且达标才算通过；“不适用”须有已确认的范围决定。无编号时引用可定位的用户要求，不另造契约。
- **汇报。** 收尾直接说明完成的验证、实际结果、未完成或受限项目及影响，并链接记录；链接和测试总数不能替代验收结论。无文件时在对话中给出同等摘要，不补建规格。

以下为 `validation-results.md` 正文模板。初始化时删除示例记录；填写时删除占位提示。覆盖表沿用契约顺序，记录按执行顺序排列。

```markdown
# <主题> — 验证结果

> 验收来源：<验收契约链接或已确认用户要求的定位>。
> 交付范围：<本次任务或拉取请求；跨次交付不混用结果>。

## 1. 当前验收覆盖

| 验收要求 | 当前状态 | 结果引用与缺口 |
|---|---|---|
| `<验收编号与短标题，或可定位的用户要求>` | 未执行 | <结果记录编号；缺口、原因和对完成判断的影响> |

> 状态：未执行 / 通过 / 失败 / 阻塞 / 待复验 / 不适用。

## 2. 验证记录

尚未执行验证。

### 验证记录-001：<验证目的>

- **关联**：<验收来源与编号，可多个；或“额外验证：目的”；复验时引用旧记录>
- **验证对象**：<执行时间、代码版本或工作树状态、必要环境>
- **执行**：<实际命令或操作路径；引用证据时注明执行来源>
- **实际结果**：<观察到的事实、关键数量或输出，以及证据局限>
- **结论**：<通过 / 失败 / 阻塞；说明能支持的判断和剩余缺口>
- **证据**：<可复核摘要、日志、截图、运行链接或其他定位；无独立附件时保留足够的实际观察>
```
