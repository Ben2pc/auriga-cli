# 项目审查者协议

项目审查者位于 `docs/rules/review/*.md`。用 `git rev-parse --show-toplevel` 定位仓库根，同时从受影响路径向上查找更近的 `docs/rules/review/`；两层都读取，冲突时子包级优先。正式拉取请求审查只执行**基准分支的可信版本**。头分支新增或修改的项目审查者仍作为审查对象，由主代理按具体风险选择审查维度，但本轮不执行，合并后才影响后续审查。非 git 仓库回退当前目录，但只有用户明确确认这些文件可信时才执行；否则列为审查缺口。

### frontmatter 字段

项目审查者必须有合法 YAML frontmatter。发现与校验阶段主代理只解析元数据；直接执行时仍须读取可信正文。

**必填：**

- `name`：kebab-case，且与文件名一致；
- `best_for` 与 `value`：非空字符串；
- `extends: <内置审查者名>`：作为宿主维度的项目专属补充；或 `extends: standalone`：作为内置维度没有覆盖的独立维度；
- `trigger`：`always` 或当前候选表支持的一个 `tag:<标签>`；
- `reasoning`：`flagship` 或 `workhorse`；
- `tools`：只包含 `Read`、`Grep`、`Glob`、`Bash`，且至少包含 `Read`。

**可选：**

- `effort`：仅在需要覆盖默认推理投入时设置，取值须受当前运行时支持，不写死模型名。

任一必填字段缺失或非法（包括 `extends` 指向不存在的宿主），都不做正文语义猜测，也不回退读取旧 `## Metadata`；将该文件列入“审查缺口”。新建审查者避免与内置名称重名；历史同名项只要元数据合法且显式声明宿主或 `standalone`，仍兼容执行。

宿主改名兼容：校验宿主是否存在前，将历史 `extends: code-quality` 解析为 `engineering-quality`，使用新宿主正文和来源名称，不产生第二个维度；新建或更新项目审查者时写新名称。此映射仅兼容旧宿主标识，不保留旧审查者文件。

被吸收的项目审查者与宿主组成一个数据包。项目审查者的 `trigger: always` 是仓库明确声明的治理门禁，必须执行相应宿主或独立数据包；`trigger: tag:<标签>` 命中时只把相应数据包加入候选，由主代理结合差异和项目规则决定是否选择。每个数据包显式携带来源标签：仅来自宿主时写 `(宿主名)`；项目补充产生的发现写 `(宿主名 / 项目审查者名)`；独立审查者写 `(项目审查者名, standalone)`。补充型审查者继承宿主的输出契约，不自行改变字段。

使用 `reviewer-creator` 创建或修正项目审查者。
