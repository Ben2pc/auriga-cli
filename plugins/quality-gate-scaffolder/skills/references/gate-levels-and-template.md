# 门禁分级和最终脚手架模板

这个文件用于给出推荐，不用于替用户做最终决定。Agent 必须把推荐档位、取舍理由和未决问题展示给用户；最终决策权属于用户。不要替用户决定档位，也不要把决策过程吞掉后直接写文件。

## 门禁分级参考表

| 分级 | 适用工程 | 门禁手段 | 规则 | 触发时机 |
| --- | --- | --- | --- | --- |
| L0：软规范 | 原型、实验仓库、一次性脚本、还没有稳定构建入口的项目 | `AGENTS.md` / `CLAUDE.md` 记录约束和人工自查项 | 目录职责、不要改哪些文件、提交前自查、测试建议、发布注意事项 | AGENTS.md 软约束 |
| L1：轻量硬门禁 | 小型长期项目、早期产品仓库、单人或少量协作 | formatter、基础 lint、typecheck 或 build、最小测试、空白检查 | 格式化规则、基础静态检查、编译或类型正确性、最小单元测试、禁止冲突标记和尾随空白 | 本地 git hook + PR 持续集成 |
| L2：生产基础门禁 | 已上线产品、多人协作主工程、已有稳定测试入口 | 统一 `tools/quality/run_gates.*`、严格 lint、typecheck、测试、规则配置测试、required check | lint 严格规则、类型基线、测试基线、配置漂移保护、依赖锁文件、基础模块边界 | 本地 git hook + PR 持续集成 |
| L3：生产级受影响门禁 | 大型移动端、后端、前端主仓库，改动频繁且全量检查较慢 | 本地 git hook + planner、自定义 gate、模块或导入边界、脚本自测、required check | 基于 diff 的受影响检查、模块边界、导入边界、本地化、部署模板、任务注册、配置漂移、自定义架构规则 | 本地 git hook + planner + PR 持续集成 |
| L4：高风险持续门禁 | 核心业务链路、复杂 monorepo、发布风险高、多人长期维护 | L3 + main 后重型检查 + 定时回归 + ruleset / CODEOWNERS | 全量构建、截图或端到端回归、安全扫描、依赖审计、部署 dry run、代码所有者审查、conversation resolution | PR 持续集成 + main 后 action + 定时 action |

## 触发时机参考表

| 触发时机 | 适合放什么 | 不适合放什么 |
| --- | --- | --- |
| AGENTS.md 软约束 | 目录职责、设计原则、人工判断、不能稳定自动化的工程背景 | 必须阻止合并的规则 |
| 本地 git hook | 空白检查、staged 格式化、轻量 lint、能秒级完成的检查 | 全量测试、构建、需要下载依赖的任务 |
| 本地 git hook + planner | 受影响模块测试、受影响 lint / typecheck、按 diff 触发的项目 gate | 需要远端权限、真机、浏览器、云服务的检查 |
| PR 持续集成 | required check、完整 lint / typecheck / test、脚本自测、配置漂移、基础架构边界 | 过慢、误报高、依赖外部环境不稳定的检查 |
| main 后 action | 全量构建、发布 dry run、平台深度 analyze、较慢但需要尽快发现的问题 | 每个 PR 已覆盖的秒级检查 |
| 定时 action | 截图回归、端到端、依赖扫描、外部服务巡检、设备或模拟器回归 | 必须阻止合并的基础规则 |

## 推荐档位原则

- 新项目默认从 L1 起。
- 已上线但规模不大，默认推荐 L2。
- 生产级主工程默认推荐 L3，但要说明维护成本。
- 只有核心链路、高发布风险或复杂 monorepo 才推荐 L4。
- 如果用户明确偏向速度，优先降一档，并把后续升级触发条件写清楚。
- 如果用户明确偏向稳定性，优先升一档，但必须说明耗时、误报和维护成本。

## 用户确认问题

在写文件之前，至少向用户确认：

- 选择哪个档位；
- 本地 hook 是否允许阻塞提交或推送；
- PR required check 的名字；
- 是否现在就启用 planner；
- main 后 action 和定时 action 是否先只给模板；
- 哪些生产级规则先不纳入本次脚手架。
